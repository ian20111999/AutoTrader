# 2026-09-29 Binance 唯讀連線（ROADMAP 第 4 步）執行計畫

## 前置狀態

使用者已提供一組 Binance API 金鑰（宣稱唯讀），已存入 macOS Keychain：
- `com.autotrader.app.binance-readonly-api-key`（帳號 `autotrader`）
- `com.autotrader.app.binance-readonly-api-secret`（帳號 `autotrader`）

**尚未確認**：使用者是否已在 Binance 後台驗證這組金鑰真的關閉了交易/提領權限、以及兩個值有沒有貼反（哪個是 key 哪個是 secret）。**在使用者確認前，不會用這組金鑰對 Binance 發出任何真正的網路請求**（4.1 可以先做，那一步不連網路）。

## 範圍

ROADMAP 4：「Binance 唯讀連線：即時行情、帳戶實際費率、下單規則（需要唯讀 API 金鑰）」。

## 子步驟

- [ ] 4.1 Keychain 存取模組：Rust 讀寫 OS 安全儲存區（macOS 鑰匙圈；Windows 認證管理員之後補），不連網路，可用假值測試
- [ ] 4.2 Binance REST client 骨架＋簽名機制：HMAC-SHA256 簽名，打一個最簡單的唯讀端點驗證（例如帳戶資訊）**——需要使用者先確認金鑰權限才能執行**
- [ ] 4.3 帳戶實際費率同步：串接 1.4 `FeeSchedule`，每 24h 從 API 更新現貨/合約費率，失敗就沿用上次值並標記日期（沿用先前架構討論定案的規則）
- [ ] 4.4 下單規則同步：串接 1.3 `SymbolRules`，從 `/api/v3/exchangeInfo` 拿到真實下單規則（價格跳動、數量級距、最小金額）
- [ ] 4.5 即時行情：WebSocket 連線拿到即時價格
- [ ] 4.6 桌面 App「連線設定」畫面：讓使用者在 App 內輸入/更新 API 金鑰（呼叫 4.1 的模組存進 Keychain），顯示連線狀態，不用再靠我手動下指令存

## 安全規則（專案 CLAUDE.md，不可違反）

- API 金鑰不寫進任何檔案/程式碼/git，只能在 OS 安全儲存區。
- 這一步（第 4 步）只做「唯讀」連線：行情、費率、規則查詢，不可以有任何送出訂單的程式碼路徑（那是第 6/7 步）。
- 第 6 步之前不可連線正式環境的下單 API——這一步本來就只碰唯讀端點，不受影響，但要小心別不小心串到下單相關端點。

## 驗證方式

沿用回測引擎/桌面App階段的模式：實作 → QA 獨立驗證（含實際跑一次真實 API 呼叫確認資料合理，但不重跑觸及帳戶變更的操作）→ 通過才 commit。4.2 之後每一步涉及真實金鑰的部分，回報時都要明確說明呼叫了哪個端點、有沒有可能觸及非唯讀操作。
