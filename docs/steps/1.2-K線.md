# 1.2 K 線與週期 `Bar`、`Interval`

## 做了什麼

新增 `crates/core/src/bar.rs`：

- **`Interval` 週期**：1m、5m、15m、1h、4h、1d。可以從 `"4h"` 這種字串轉換，`millis()` 算出一根 K 線有幾毫秒。
- **`Bar` K 線**：開盤時間（UTC 毫秒）、開高低收（`Fixed`）、成交量（`f64`）。`validate()` 檢查單根是否合理。
- **`find_gaps()`**：檢查一串 K 線的時間順序，並列出中間缺了哪幾段。

## 為什麼要這樣做

回測引擎只吃 K 線。K 線有錯，回測結果就一定錯，而且錯得很安靜：
一根最高價比收盤價還低的 K 線，可能讓停損「看起來」沒被觸發。所以資料一進來就先檢查。

## 幾個設計決定

- **價格用 `Fixed`、成交量用 `f64`**：價格會拿去算下單和損益，必須精確；成交量只用在統計（例如均量），差一點點沒關係。
- **時間用 UTC 毫秒**：和 Binance API 一樣，不處理時區，避免夏令時間之類的問題。
- **週期字串區分大小寫**：Binance 的 `1m` 是一分鐘，大寫 `1M` 是一個月。如果不分大小寫，打錯一個字就會把月線當分線用。
- **錯誤和缺口分開處理**：
  - 時間倒退、重複、沒對齊週期（例如 4 小時 K 線在 01:00 開盤）→ 回傳錯誤，因為資料本身壞了。
  - 中間缺了幾根 → 只列出來，不當成錯誤。交易所維護時真的會缺資料，回測要能處理這種情況。

## 怎麼驗證

在專案資料夾執行：

```bash
cargo test -p at-core bar
```

應該看到 14 個 `bar::tests::...` 全部 `ok`。

## 建議閱讀順序

1. 最下面的測試：`capital_m_is_a_month_not_a_minute`、`gaps_are_reported_not_rejected`
2. `Bar::validate`：單根 K 線的檢查
3. `find_gaps`：一串 K 線的檢查，注意 `rem_euclid` 怎麼判斷有沒有對齊週期

## 動手試試看

1. 在 `capital_m_is_a_month_not_a_minute` 裡把 `"1M"` 改成 `"1m"`，跑測試看它失敗，再改回來。這就是為什麼不能自動轉小寫。
2. 在 `gaps_are_reported_not_rejected` 的時間清單中間多加一根 `T0 + 5 * h`，猜猜第二個缺口會怎麼變，再跑測試驗證。
