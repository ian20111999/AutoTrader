# 3.6 回測頁面

這一步分兩段完成：Rust↔前端橋接（`run_backtest_command`，commit `5da7b7d`，另一個 agent 做的）
和這裡記錄的前端 UI（資料選擇表單、執行、結果顯示）。

## 做了什麼

新增六個檔案：

- `app/src/backtestTypes.ts`：跟 `app/src-tauri/src/backtest.rs` 的 `BacktestRequest`/
  `BacktestSummary`/`EquityPointDto` 對應的 TypeScript 型別。
- `app/src/backtestFormat.ts`：把 Rust 端的比例字串（`"0.198"` 代表 19.8%）轉成畫面用的
  百分比文字，正負號、null 顯示「—」的規則集中在這裡，附 `backtestFormat.test.ts`。
- `app/src/EquityCurveChart.tsx`：手刻的 SVG 折線圖，畫 `curve` 陣列。
- `app/src/BacktestResult.tsx`：權益曲線＋四個績效指標＋交易統計＋成本假設誠實標示。
- `app/src/Backtest.tsx`：資料選擇表單（策略回顯、交易對、週期、年月、起始資金）＋
  loading/error/success 三態切換＋呼叫 `run_backtest_command`。
- `App.tsx` 接上 `<Backtest strategyConfig={strategyConfig} onGoToStrategies={...}>`，
  拿掉 3.6 之前的佔位文字。

## 為什麼要這樣做

### 圖表方案：手刻 SVG，不加圖表函式庫

現在只需要畫一條線（單次回測的權益曲線）。原生 SVG（`<polyline>` + 兩個文字標籤 + 一條
起始資金基準虛線）大概 40 行就做完，不需要學一個函式庫的 API、不增加 bundle 大小、也不用
在專案裡多維護一個依賴的版本升級。這是 ladder 規則「平台原生有就不裝依賴」的直接應用；
設計稿本身（`Strategies.dc.html`、`StrategyEditor.dc.html` 的權益曲線縮圖）也都是手刻 SVG
path，風格上一致。

3.7（回測比較頁面）需要疊圖比較「多條」曲線，那時候的需求可能還包含：不同時間軸怎麼對齊、
要不要正規化成報酬率而不是絕對權益、多條線的 legend/tooltip 怎麼互動——這些現在都還不知道
確切要什麼形狀。與其現在猜一個函式庫的 API 剛好符合 3.7 的需求（猜不準就是白工），不如等
3.7 動工、需求明確了再決定要不要上函式庫。如果那時候真的需要，會是一個引入一般 runtime
依賴的正常決策（不涉及認證/付費/安全層），不需要現在預先決定。

### 資料選擇表單

- **交易對**：純文字輸入框，預設 `BTCUSDT`。`Symbol::new()` 的格式驗證留給 Rust 端做（已經
  有「交易對代號不合法：{e}」的清楚錯誤訊息），前端只擋「不能是空白」，不重複實作一份
  Symbol 格式規則。
- **週期**：原生 `<select>` 六選一（1m/5m/15m/1h/4h/1d），對應 `at_core::Interval` 支援的值。
  六個固定選項用原生下拉選單就夠，不需要自訂元件。
- **年月**：原生 `<input type="month">`，直接產生 `"YYYY-MM"` 格式，送出前 split 成
  year/month 兩個數字。比另外做兩個 number input 或自訂日期選擇器都簡單——這是 ladder 規則
  「平台原生有」的另一個例子。
- **起始資金**：文字輸入＋正則驗證（必須是正數），跟 3.5 `StrategyParamForm` 的 decimal
  驗證是同樣的模式（`^\d+(\.\d+)?$` + 檢查 `> 0`），錯誤訊息用 `aria-describedby` 關聯。

### 策略哪裡來、選不到策略時怎麼辦

`Backtest.tsx` 不直接吃 `strategyConfig.strategyId`（一個像 `"sma_cross"` 的技術代號）當畫面
文字，而是自己呼叫一次 `list_builtin_strategies` 找到對應的 `StrategyInfo`，顯示
`"均線交叉：快線週期5、慢線週期20"` 這種人看得懂的摘要（跟 3.4 `paramSummary` 同樣的組字
邏輯，只是資料來源從 `param.default` 換成 `strategyConfig.values`）。這裡沒有把策略清單提到
`App.tsx` 共用快取——3.4/3.5 至今每個需要策略中繼資料的頁面都是各自呼叫一次
`list_builtin_strategies`（一個本機讀取、沒有下載，成本很低），加一層共用快取是還沒有遇到
效能問題就先做的預先優化，不划算。

`strategyConfig` 為 `null`（使用者還沒去 3.5 套用過參數）時，不是灰掉整個表單disabled了事，
而是給一個 `role="alert"` 的提示訊息＋一顆「前往策略庫」按鈕，直接呼叫 `onGoToStrategies`
切換到策略庫分頁——這顆按鈕不是「看起來能點但沒反應的假按鈕」，點下去是真的會切分頁的正常
導覽功能。

### loading/error 狀態

`run_backtest_command` 第一次遇到某個月份會觸發真實下載，可能要等，所以：

- 送出後立刻 `setStatus("loading")`，用 `<fieldset disabled={status === "loading"}>`
  包住整組表單欄位——原生 `fieldset disabled` 會自動讓底下所有 `<input>`/`<select>`/
  `<button>` 變成不可互動，不用自己一個一個欄位加 `disabled` 屬性（同樣是 ladder 規則的
  應用）。手動用 Playwright 開真的瀏覽器驗證過，確實所有欄位都被鎖住（見下方「怎麼驗證」）。
- 執行按鈕文字從「執行回測」變成「回測中…」，主內容區顯示 `role="status"` 的提示文字，
  明講「第一次跑這個月份會先下載，可能需要一些時間」，不讓使用者以為當機。
- 失敗時 `catch` 區塊把 `status` 設回 `"error"`、顯示 `role="alert"` 的錯誤訊息（直接顯示
  Rust 端回傳的中文錯誤字串，例如「找不到⋯」「參數 xxx 不是合法數字」），不會卡在 loading，
  表單也重新可以編輯。

### 成本假設的誠實標示

`feeModel`/`slippage` 是 Rust 端目前寫死的系統預設（`backtest.rs` 註解：ponytail 手續費/
滑價目前寫死成 VIP0 + 0.05% 滑價，3.6 還沒有對應的 UI 控制項）。`BacktestResult` 用小字
斜體＋明講「系統目前固定使用，還不能由你調整」顯示這行字，不會讓使用者誤以為這是自己
調過的設定——這是團隊主管在派工時特別點名的要求。

### 績效指標的格式化

讀了 `crates/core/src/metrics.rs` 確認：`total_return`/`annualized_return`/`max_drawdown`/
`sharpe` 全部是**比例**字串（`"0.25"` 代表 25%），不是已經乘過 100 的數字；`max_drawdown`
永遠是正數量級（`"0.19"` 代表跌了 19%，Rust 端保證「永遠算得出來，不是 `Option`」）；
其他三個是 `Option<Fixed>`，`None` 代表 Rust 端「算不出來」（曲線太短、除以 0…），畫面上
顯示「—」而不是假造一個 0——跟 Rust 端「算不出來就回 None，不回一個假數字」的原則一致，
沒有在前端偷偷把 `null` 當成 0 處理。

## 3.6 範圍取捨（對照設計稿 `Backtest.dc.html`）

設計稿是完整的策略研究工作台：左側除了資料選擇還有市場/方向切換、保證金模式、槓桿拉桿、
10 幣種多選、進出場週期拉桿即時調參、手續費來源選擇、「計入真實歷史資金費率」開關、參數
掃描／另存版本按鈕；中間除了權益曲線還有「健檢摘要」（3 項良好、2 項注意的規則式健檢）、
6 個指標卡（含近 12 月報酬、手續費+滑價拖累、資金費拖累）、儲存回測/加入比較/開始模擬/
部署四個動作；右側是「參數穩定度」熱力圖（掃描 N×M 參數組合的年化報酬矩陣，點格子套用）
和「逐年表現」表格、「各幣種貢獻」長條圖。

這個 App 現在只有一支 `run_backtest_command`，一次呼叫對應「一個交易對、一個月份、一組
固定參數」，沒有多幣種、沒有槓桿/保證金/資金費率的 UI 控制項（Rust 端目前寫死現貨
frictionless 設定）、沒有參數掃描（那需要對同一組資料跑很多次回測，是全新的功能，不是
UI 排版問題）、沒有「儲存回測」的持久化機制、也還沒有比較頁面可以「加入比較」。所以 3.6
只做「選資料→跑一次→看這一次的權益曲線和四個指標」這個最小可用的迴圈，其餘全部先不做——
硬做健檢摘要、參數穩定度矩陣這些需要大量假設或根本沒有資料支撐的區塊，只會是编造數字或
連不到任何真實邏輯的假功能。

## 給 3.7（回測比較頁面）的銜接說明

- `BacktestSummary` 目前**只存在 `Backtest.tsx` 的本地 state**（`useState`），不像
  `strategyConfig` 那樣被拉到 `App.tsx`。3.7 需要「多次回測結果」，資料形狀是一個
  `BacktestSummary[]` 陣列而不是單一值，跟 `strategyConfig` 的單值狀態不是同一種東西，
  現在先猜這個陣列要長什麼樣（要不要分頁？要不要持久化到磁碟？）沒有意義。
- 3.7 動工時，做法應該跟 3.5→3.6 的接法一樣：在 `App.tsx` 加一個新的 state（例如
  `savedBacktests: BacktestSummary[]`），`Backtest.tsx` 在拿到結果後多一顆「加入比較」
  按鈕呼叫 `onAddToCompare(summary)` 把當次結果 push 進那個陣列，`Compare.tsx` 讀那個
  陣列畫表格/疊圖。
- `EquityCurveChart` 現在只支援畫一條線；3.7 疊圖需要重新設計成能接受多條 `curve` 的版本
  （或者到時候才決定要不要換圖表函式庫，見上面「圖表方案」那一節的取捨）。
- `BacktestSummary` 已經把這次跑用的完整設定（`symbol`/`interval`/`year`/`month`/
  `strategyId`/`strategyName`/`params`/`startingCapital`/`feeModel`/`slippage`）都回顯在
  結果裡（`backtest.rs` 的註解也寫了「方便 3.7 比較頁面直接把整個結構存起來比較」），
  3.7 不需要額外呼叫任何 API 補資料，直接用存起來的 `BacktestSummary` 物件就有比較表格
  需要的全部欄位。
