# 2.7 內建策略：均線交叉、布林通道、唐奇安突破、RSI

## 做了什麼

新增 `crates/core/src/strategies/` 這個模組，裡面是四個可以直接拿去回測的策略，
每一個都 `impl Strategy`（2.1 的介面），所以 2.2 的回測迴圈不用改一行就能跑它們。

| 檔案 | 型別 | 類型 | 進場 | 出場 |
|---|---|---|---|---|
| `sma_cross.rs` | `SmaCross` | 趨勢跟隨 | 快線 > 慢線 | 快線回到慢線之下 |
| `bollinger.rs` | `Bollinger` | 均值回歸 | 收盤 ≤ 下軌 | 收盤 ≥ 中軌 |
| `donchian.rs` | `Donchian` | 趨勢跟隨 | 收盤 > 前 N 根最高價 | 收盤 < 前 M 根最低價 |
| `rsi.rs` | `Rsi` | 均值回歸 | RSI ≤ 進場門檻 | RSI ≥ 出場門檻 |
| `mod.rs` | `Window`、`WilderAverage`、`StrategyParamError` | 共用零件 | — | — |

四個策略目前都只有「滿倉做多」與「空手」兩種目標部位。介面本身支援做空
（`TargetPosition` 是帶正負號的比例），但現貨沒有做空，所以等 2.5 合約做完
再決定要不要加反手版本。

### 參數與預設值

每個策略的參數都從建構子傳入，不合理的組合直接回傳 `StrategyParamError`，
不會等到 `on_bar` 才算出奇怪的結果（參數之後會從桌面介面的輸入框來）。

| 策略 | 參數 | 預設值 | 擋掉什麼 |
|---|---|---|---|
| `SmaCross::new(fast, slow)` | 快線、慢線週期 | 10 / 50 | 週期 0；快線沒有短於慢線 |
| `Bollinger::new(period, multiplier)` | 週期、標準差倍數 | 20 / 2 倍 | 週期 0；倍數 ≤ 0 |
| `Donchian::new(entry, exit)` | 進場、出場週期 | 20 / 10 | 週期 0 |
| `Rsi::new(period, buy_below, exit_above)` | 週期、超賣門檻、超買門檻 | 14 / 30 / 70 | 週期 0；門檻不在 0～100；進場門檻沒有低於出場門檻 |

四個都有 `Default`，值就是上表的預設值。

設計稿的範例畫的是唐奇安 100/10、布林 20 日/1.5 倍、均線 10/50、RSI 14/20/50。
這裡的預設值取教科書上的經典設定（唐奇安 20/10、布林 2 倍、RSI 30/70），
設計稿那幾組數字用建構子傳進去就有，兩者不衝突。

### 暖機邏輯

`warmup_bars()` 回報「至少要先餵幾根，訊號才有意義」，四個策略的答案不一樣：

| 策略 | `warmup_bars()` | 為什麼 |
|---|---|---|
| `SmaCross` | 慢線週期 | 慢線滿了，兩條線才都有值 |
| `Bollinger` | 週期 | 中軌與標準差都要整個視窗 |
| `Donchian` | max(進場, 出場) **+ 1** | 通道是用「這根之前」的 N 根算的，判斷用的那根本身不算在視窗裡 |
| `Rsi` | 週期 **+ 1** | N 筆漲跌幅要 N+1 根 K 線才算得出來 |

但 `warmup_bars()` 只是**宣告**，不是保護。真正的保護在指標層：
`Window` 的 `mean`、`stddev`、`highest`、`lowest` 在視窗沒滿時一律回傳 `None`，
策略把 `None` 對應到「空手」，暖機期就自動安全——**不 panic、也不拿半個視窗亂猜**。
每個策略都有一個「暖機期就算行情很極端也必須空手」的測試釘住這件事。

## 為什麼這樣設計

### 共用一個 `Window`，而不是每個策略各寫一套 rolling window

四個策略的指標都是「最近 N 根的某個統計量」，差別只在統計量是平均、標準差
還是最高最低。所以 `mod.rs` 放一個 `Window`：

- 移動總和用 `i128` 累加，推進一根是 **O(1)**（減掉最舊的、加上最新的），
  不是每根重掃整個視窗。用 `i128` 的好處是「N 個 `i64` 相加一定放得下」，
  於是加總本身永遠不會溢位，`push` 不需要回傳 `Result`。
- `stddev`、`highest`、`lowest` 是 **O(N)** 掃視窗。N 是使用者設定的週期
  （通常 14～200），K 線根數才是資料量，所以整場回測是 O(根數 × N)，不是 O(根數²)。
  這裡刻意沒有寫單調佇列（可以把最高最低壓到 O(1)）——先求簡單正確，
  程式裡用 `ponytail:` 註解標了「等實測發現這裡是瓶頸再換」。

### 指標也全部用 `Fixed` 算，連標準差都不用 `f64`

專案規範只要求「下單相關計算不可用 `f64`」，指標值嚴格來說不是下單金額。
但訊號會決定要不要下單，而 `f64` 的加總順序會影響最低位的結果：同一份資料在
回測與實盤可能因為浮點誤差落在門檻的兩邊，變成「回測有這筆交易、實盤沒有」。

所以標準差也用整數算：離差平方是 10^16 倍，**開整數平方根後剛好回到 10^8 倍**，
不必再縮放。平方根自己寫了一個牛頓法的 `isqrt`（標準庫的 `u128::isqrt` 要
Rust 1.84，本專案宣告的 `rust-version` 是 1.80）。

代價是除法會截尾（往零的方向）：3 根 10 / 20 / 31 的均線是 `20.33333333`，
√5 是 `2.23606797`。第 8 位小數以下的差異不影響訊號判斷，而且**每次都一樣**。

### 均線交叉：比大小，不偵測「交叉事件」

策略回傳的是目標部位不是訂單，所以「偵測到向上交叉就買、向下交叉就賣」和
「快線在上面時目標是滿倉、在下面時目標是空手」產生的部位序列**完全一樣**，
但後者不必記住上一根的兩線關係，也不會因為第一根沒有前一根而漏掉訊號。

兩線相等時是空手：寧可少做一筆，也不要開一個沒有理由的倉。

### 布林通道與 RSI 要記住「還抱著」

進場條件（碰到下軌、RSI 跌到 30 以下）常常只成立一瞬間。如果不記住部位，
下一根價格離開下軌就立刻平倉，等於完全沒有參與均值回歸那一段。
所以這兩個策略有一個 `holding` 欄位，收盤落在進出場條件之間時**維持上一根的部位**。

寫這段時踩到一個邊界：**價格完全不動時標準差是 0，三條線重疊**，
收盤價同時滿足「≤ 下軌」和「≥ 中軌」。如果進場條件先判斷，零波動的盤整
會被當成「碰到下軌」而開倉。所以 `Bollinger::on_bar` 把**出場條件放在前面**判斷：
標準差 > 0 時兩個條件互斥、順序不影響結果，只有退化的情況會用到這個順序，
而那時候正確答案是空手。測試 `a_flat_market_has_no_band_width_and_stays_flat`
就是釘這條規則。

### 唐奇安：通道不含當下這根

如果把當下這根的最高價也算進通道，收盤價永遠不可能高過「含自己的最高價」，
訊號會永遠不出現。所以 `on_bar` 是**先用現有視窗判斷，判斷完才把這根放進視窗**
（程式裡就是 `let channel = (...)` 寫在兩個 `push` 之前的那三行）。

另外通道用最高／最低價、突破判斷用**收盤價**：用盤中最高價判斷突破的話，
回測會假設一根 K 線之內就成交，但引擎的規則是訊號在收盤產生、下一根開盤成交
（2.3），用收盤價判斷才對得上實際能成交的時點。

「創新高」是嚴格大於：收盤等於前 N 根最高價不算突破。

### RSI 用 Wilder 平滑，不是單純的移動平均

平均漲跌幅有兩種算法：

| 算法 | 公式 | 誰在用 |
|---|---|---|
| **Wilder（採用）** | 前 N 筆先取算術平均當種子，之後 `新平均 = 舊平均 + (這筆 − 舊平均) ÷ N` | TradingView、ta-lib、Binance 介面上的「RSI」 |
| Cutler's | 直接取最近 N 筆的算術平均 | 少數自製指標 |

兩者的數值不一樣。這裡用 Wilder，因為 **2.8 要和之前的 Python 回測對照**，
用同一個定義才對得上——如果那邊是 ta-lib 或 pandas-ta 算的，就是 Wilder。

遞推式刻意寫成 `舊平均 + (這筆 − 舊平均) ÷ N` 而不是常見的
`(舊平均 × (N−1) + 這筆) ÷ N`：兩者數學上相同，但前者的中間值一定落在
「舊平均」與「這筆」之間，所以**不可能溢位**，不必在每根 K 線上處理一個
永遠不會發生的錯誤。

一個要注意的副作用：Wilder 平滑理論上會記得所有歷史（每根只衰減 1/N），
所以 `warmup_bars()` 回報的 `週期 + 1` 只是「算得出數值」的最低根數；
數值要收斂到和「從更早開始餵」幾乎一致，通常還要再幾個週期。
**對照驗證時兩邊一定要從同一根 K 線開始餵**，不然會被這個差異絆住。

漲跌幅全是 0 時 RSI 在數學上無定義（分母是 0），這裡取中性值 50，
落在預設的兩個門檻之間，所以結果是空手。

## 怎麼驗證

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
```

三個都要沒有輸出／沒有警告／全綠。只跑這一步的測試：

```bash
cargo test -p at-core strategies::
```

應該看到 48 個測試全部 `ok`（全專案共 142 個）。每個策略都有這三類測試：

| 類型 | 例子 | 在驗什麼 |
|---|---|---|
| **指標數值** | `rsi_value_matches_hand_calculation` | 手算的 SMA / 標準差 / 通道 / RSI 和程式算的一樣——不是只看訊號方向 |
| **暖機保護** | `stays_flat_until_warmed_up_even_while_crashing` | 資料不夠時就算行情很極端也回空手 |
| **訊號序列** | `buys_oversold_holds_then_exits_overbought` | 手算過的一段價格，進場／續抱／出場三種狀態都走到 |

訊號序列的預期值寫成一個字串，`.` 是空手、`L` 是做多，一眼就能看完：

```rust
let bars = closes(&["100", "99", "98", "97", "96", "98", "110"]);
assert_eq!(signals(&mut s, &bars), "....LL.");
```

每個策略還有一個 `extreme_prices_do_not_panic`：餵 `i64` 上限附近的價格，
確認 `Strategy` 契約裡「不可 panic」那條在溢位時仍然成立。

## 建議閱讀順序

1. `strategies/mod.rs` 最上面的表格與「為什麼指標也用 `Fixed` 算」
2. `Window`：四個策略共用的 rolling window，注意每個統計量在視窗未滿時都回 `None`
3. `sma_cross.rs`：最短的一個，先看它怎麼把 `None` 變成空手
4. `donchian.rs` 的 `on_bar`：`let channel = (...)` 為什麼一定要寫在 `push` 之前
5. `bollinger.rs` 的 `on_bar`：為什麼出場條件寫在進場條件前面
6. `rsi.rs` 的 `WilderAverage`：兩階段（種子期／遞推期）怎麼用一個 `Option` 表示
7. 四個檔案的測試——每個測試上面的註解就是手算過程

## 動手試試看

1. 把 `Bollinger::on_bar` 裡的兩個條件對調（進場寫前面），跑 `cargo test`。
   `a_flat_market_has_no_band_width_and_stays_flat` 會失敗：程式會在完全沒有
   波動的盤整裡開倉。這是「回測看起來還很正常，但多做了一堆不該做的交易」
   那種錯，只有測試抓得到。
2. 把 `donchian.rs` 裡的 `let channel = (...)` 移到兩個 `push` 之後，跑測試。
   `breaks_out_holds_then_exits_on_a_new_low` 會失敗——收盤價不可能高過
   「含自己的最高價」，這個策略會永遠不進場。
3. 自己算一次：`Rsi::new(4, ...)` 餵收盤價 100 → 104 → 100 → 100 → 100 → 104，
   先用紙筆算出第 5 根與第 6 根的 RSI（提示：種子期的平均漲幅與跌幅都是 1），
   再跑 `cargo test -p at-core rsi_value_matches_hand_calculation` 對答案。
4. 把 `Rsi` 改成 Cutler's（直接用最近 N 筆的算術平均），跑同一段資料，
   看兩個定義差多少。這就是 2.8 對照驗證時，如果 RSI 數字對不上要先懷疑的地方。
5. 用 2.2 的回測迴圈把四個策略跑同一份 K 線（`Vec<Box<dyn Strategy>>` 裝得下），
   看哪一個在這段行情裡交易次數最多——趨勢跟隨與均值回歸的差別會很明顯。
