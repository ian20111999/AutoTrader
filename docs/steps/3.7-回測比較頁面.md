# 3.7 回測比較頁面

## 做了什麼

新增五個檔案：

- `app/src/compareColors.ts`：疊圖跟圖例共用的調色盤（6 色循環），拆成獨立檔案是為了讓
  `CompareChart.tsx` 只匯出元件（滿足 React Fast Refresh 的 lint 規則），也讓
  `Compare.tsx` 的圖例色塊跟圖表的線條顏色保證用同一份對照表，不會兩邊各寫一份、之後
  改了一邊忘了改另一邊。
- `app/src/CompareChart.tsx`：多條權益曲線疊圖，把每筆回測的權益曲線轉成「相對起始資金的
  累積報酬%」再疊在同一張圖上（見下方「圖表方案」）。
- `app/src/Compare.tsx`：比較頁面主體——圖例、疊圖、指標比較表格、空狀態、移除功能。
- 改 `app/src/Backtest.tsx`：結果區加「加入比較」按鈕，呼叫新的 `onAddToCompare` prop，
  按過一次之後按鈕會鎖住變成「已加入比較 ✓」，換一次新的回測結果會重新解鎖。
- 改 `App.tsx`：新增 `savedBacktests` state（`BacktestSummary[]`），接上
  `<Compare savedBacktests={...} onRemove={...} onGoToBacktest={...}>`，拿掉 3.7 之前的
  佔位文字。
- 把 `BacktestResult.tsx` 裡原本本地定義的 `signClass`（依正負值決定顏色 class）搬到
  `backtestFormat.ts` 匯出，因為 `Compare.tsx` 的表格欄位需要同一套上色規則，兩個地方
  各寫一份會有規則跑掉的風險。

## 圖表方案這次的決定：繼續手刻 SVG，理由跟 3.6 不同

3.6 的判斷是「疊圖需求還不明確，不知道要不要對齊時間軸、要不要正規化、要不要
tooltip/縮放，猜一個函式庫的 API 剛好符合猜不準就是白工，先不選」。這一步需求具體了，
重新評估後的結論還是手刻 SVG，但理由不一樣：

- **複雜度還是線性成長，不是質變。** 疊圖需要的東西——多畫幾條 `<polyline>`、一個顏色
  循環、一個文字圖例——每多一筆回測就多一條線、多一個圖例項目，跟畫一條線的複雜度是
  同一個量級，不是需要全新的資料結構或渲染模型。
- **沒有真的需要函式庫解決的互動需求。** 這一步沒有要做 tooltip（滑過某個點顯示數字）、
  沒有要做縮放/拖曳、沒有要做 log 座標切換——這些才是函式庫真正的價值所在。目前的需求
  純粹是「畫出來、看得出形狀、看得出顏色對應哪筆」，原生 SVG 完全夠。
- **時間軸對齊問題有更簡單的解法，不需要函式庫幫忙。** 每筆回測是不同交易對/不同月份，
  時間戳完全對不上；解法不是找一個支援「多時間軸疊圖」的函式庫，而是換一個更適合比較的
  座標系——見下面「疊圖怎麼對齊」。這個轉換本身是純資料處理，跟畫圖工具無關，即使真的用
  了函式庫，這一步的資料轉換還是要自己寫。

如果 3.7 之後真的需要 tooltip、縮放、或者要支援使用者自己選要不要正規化，那才是重新
評估要不要上函式庫的時機——跟 3.6 的判斷邏輯一致，只是這次評估後的需求剛好還在原生 SVG
划算的範圍內。

## 疊圖怎麼對齊：相對進度 × 累積報酬%

直接照 `openTime`（真實時間戳）畫在同一個時間軸上行不通：兩筆回測可能是完全不同的月份
（例如 2024/01 vs 2024/02），時間戳範圍互不相交，硬疊在一起只會讓每條線各自散落在圖的
不同角落，看不出任何比較意義。

`CompareChart.tsx` 的 `toReturnSeries` 把每筆回測的權益曲線轉成「相對起始資金的累積報酬
%」（`(equity / startingCapital - 1) * 100`），X 軸則用「這筆回測跑到第幾根 K 線的相對
位置（`index / (length - 1)`，0～1）」而不是真實日期。這樣一次解決兩個問題：

1. 不同起始資金的回測可以疊在同一個 Y 軸上比較（都從 0% 附近開始）。
2. 不同長度、不同月份的回測可以疊在同一個 X 軸上比較「形狀」（回測期間過了多少比例）。

代價是 X 軸不是真的日曆時間，只是「回測期間跑了多少比例」——圖表的 `aria-label` 有寫清楚
這件事（「橫軸是各自回測期間的相對進度，不是日曆時間」），沒有假裝這是對齊過的真實時間軸。
如果之後兩筆回測剛好是同一個月份、同樣長度，這個簡化不會造成誤導；月份不同時，這張圖回答
的問題是「這兩個策略的報酬曲線形狀/波動特徵像不像」，不是「這兩個策略在同一段真實時間各自
表現如何」——這是刻意的簡化，不是疏漏。

## 表格設計

`<table>` 一筆回測一列：顏色色塊（跟疊圖/圖例同一個顏色）、策略名稱＋參數摘要（兩行，跟
3.4/3.5/3.6 同樣的組字模式）、資料範圍（交易對·週期·年/月）、總報酬／年化／最大回撤／夏普
四個指標（沿用 3.6 `backtestFormat.ts` 的格式化＋上色規則）、交易次數、移除按鈕。

參數摘要用策略的 `label`（例如「快線週期5」而不是「fastPeriod5」）：`Compare.tsx` 自己呼叫
一次 `list_builtin_strategies` 建一個 `strategyId → StrategyInfo` 的對照，找不到（還在讀取
中）就退回顯示原始 key=value。跟 3.6 `Backtest.tsx` 同樣的判斷——每頁各自呼叫一次是本機
讀取、成本很低，沒有做一個跨頁共用快取的必要。

移除功能只放在表格（每列一個「移除」按鈕），圖例列表（疊圖上方的顏色圖例）是純資訊展示、
沒有互動——避免同一個「移除」動作在畫面上出現兩套不同的觸發點，維護時只要改一個地方。

## 3.7 範圍取捨（對照設計稿 `Compare.dc.html`）

設計稿的疊圖除了策略線，還有一條 BTC 買入持有的基準線（虛線）；表格除了現在做的四個指標，
還有 2024/2025/2026 至今/近 12 個月四個「逐年報酬」欄位、一個「市場」欄位（現貨/合約/槓桿
倍數）、還有一整排「只改槓桿1x→2x」「做多 vs 多空」這種自動生成的洞察卡片、指標欄位還會
標示「本欄最佳」的底色。

這個 App 現在的 `BacktestSummary` 是「一個交易對、一個月份」的單次回測結果，沒有跨年份的
逐年拆解（那需要用同一組參數連續跑好幾個月甚至好幾年的回測，是全新的批次執行功能，不是
表格排版問題）、沒有 BTC 買入持有的對照數據（沒有算過這個指標）、沒有市場/槓桿欄位
（Rust 端目前寫死現貨 frictionless）、也沒有生成洞察文字的邏輯（那些是讀了多組數字之後
歸納出的觀察句，需要規則引擎或至少一些統計比較邏輯，現在的資料量——通常兩三筆——也不夠讓
這種歸納有意義）。所以 3.7 只做「並排看已經跑出來的幾筆結果的四個指標＋疊圖比較形狀」，
其餘全部先不做——硬做本欄最佳標示或洞察卡片，在資料量只有兩三筆時不會有實際幫助，還可能
暗示系統有更深的分析能力，誤導使用者。

`savedBacktests` 目前只存在記憶體（`App.tsx` 的 `useState`），沒有持久化：關掉 App 或切換
分頁之外的操作（例如重新整理，桌面 App 用不到，但邏輯上）就會清空。設計稿裡「回測紀錄 12
筆」暗示有一個持久化的回測歷史資料庫，這個 App 目前完全沒有儲存機制（沒有本機資料庫、沒有
檔案持久化 API），加這個是全新的資料層功能，不在 3.7 的範圍內。

新增/修改的測試檔：

- `CompareChart.test.tsx`：每筆回測畫一條線；資料點不足的回測不畫線但不影響其他回測正常
  畫出來；全部回測都沒有足夠資料（或陣列是空的）時顯示文字說明，不畫空圖表；`colorForIndex`
  同一個 index 永遠回傳同一個顏色、不同 index 循環使用調色盤。
- `Compare.test.tsx`：沒有比較項目時的空狀態與「前往回測」導覽；只有一筆時表格與圖表照樣
  完整顯示；多筆回測時表格列數正確、不同策略的參數摘要依各自的 label 組字；點移除按鈕呼叫
  `onRemove` 並帶正確的 index；`null` 指標顯示「—」。
- `backtestFormat.test.ts`：新增 `signClass` 的三個測試（正值/負值/0 與 null 都不套色）。
- `Backtest.test.tsx`：新增「加入比較」呼叫 `onAddToCompare`、按鈕鎖住變成已加入狀態；
  重新執行回測後「已加入比較」狀態會重置成可以再加一次。

離線／實跑驗證：用 Playwright 開 `npm run dev`，掛 `window.__TAURI_INTERNALS__.invoke` 的
mock（`list_builtin_strategies` 回傳兩個策略、`run_backtest_command` 依請求的月份回傳不同
的假 `BacktestSummary`，一個正報酬一個負報酬），實際走了完整流程：

1. 空狀態：切到比較分頁（還沒加過任何回測）→ 看到「還沒有加入任何回測」提示 → 點「前往
   回測」→ 真的切到回測分頁。
2. 策略庫選「均線交叉」調成快線5/慢線20 → 套用 → 切到回測頁 → 執行 2024/01 的回測 → 結果
   正確顯示（總報酬+5.0%、年化+60.0%）→ 點「加入比較」。
3. 策略庫選「RSI」調成進場25/出場75 → 套用 → 切到回測頁（策略欄位正確顯示「RSI：週期14、
   進場門檻25、出場門檻75」，證明 3.5 的 `strategyConfig` 正確反映最新選的策略）→ 改年月
   為 2024/02 → 執行 → 結果正確顯示（總報酬−5.0%、年化−60.0%，負值正確用紅色）→ 點「加入
   比較」。
4. 切到比較分頁 → 兩筆資料都正確顯示：圖例兩個色塊（amber、blue）＋策略名稱與資料範圍；
   疊圖兩條不同顏色的折線；表格兩列，指標數字正確、正負號顏色正確、參數摘要用正確的策略
   label 組字（「快線週期5、慢線週期20」「週期14、進場門檻25、出場門檻75」，不是原始 key
   名稱）（截圖）。
5. 點第一列「移除」→ 表格/圖例/疊圖都正確更新成只剩一筆（截圖）。

根目錄 `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、
`cargo test`：195+10+3+1 個測試數量不變，這次改動完全沒碰 `crates/` 或 `app/src-tauri`。

## 建議閱讀順序

1. `app/src/compareColors.ts`：顏色怎麼循環分配
2. `app/src/CompareChart.tsx`：先看 `toReturnSeries`（為什麼要轉成相對報酬%），再看
   `plottable`（怎麼濾掉資料點不足的回測而不影響其他線的顏色）

4. `app/src/Compare.tsx`：`paramSummaryFor` 怎麼解析出 label、表格欄位怎麼對應
   `backtestFormat.ts` 的格式化函式
5. `app/src/Backtest.tsx` 的 `handleAddToCompare`／`addedToCompare`：加入比較的狀態怎麼
   跟著新的回測結果重置
