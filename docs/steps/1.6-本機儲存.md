# 1.6 本機儲存 `write_bars_file`、`read_bars_file`

## 做了什麼

新增 `crates/core/src/bar_store.rs`：

- **`write_bars_file(bars, path)`**：把 `Vec<Bar>` 存成本機文字檔。
- **`read_bars_file(path)`**：從檔案讀進來、解析回 `Vec<Bar>`。
- **`format_bars(bars)` / `parse_bars(content)`**：不碰檔案系統的版本，方便單獨測格式本身。
- **`BarStoreError`**：讀寫失敗的原因，附「第幾行」方便定位問題：
  - `WrongFieldCount`：那一行不是 6 欄。
  - `BadNumber`：某一欄不是合法數字（附欄位名稱）。
  - `Io`：讀寫檔案失敗（檔案不存在、沒權限、格式以外的問題等）。

## 儲存格式

逗號分隔、無 header、每行一根 K 線，只存 `Bar` 真正有的 6 個欄位：

```
open_time(ms), open, high, low, close, volume
```

跟 1.5 的 Binance CSV 長得像，但欄位數不同（6 欄不是 12 欄）——這是專案自己的格式，不是 Binance 的格式，所以沒有重用 `kline_csv` 的解析器，而是照同樣的寫法（`parse_field` 泛型函式、「第幾行」錯誤）另外寫一份，兩份程式碼看起來相似是因為問題本身相似，不是抽共用元件的理由（欄位數不同，硬共用反而要多繞一層）。

## 幾個設計決定

- **不加外部套件**：這個 workspace 到目前為止零第三方依賴。`Bar` 的欄位只有 `i64`、`Fixed`、`f64` 三種，三者都已經有 `Display`/`FromStr`（`Fixed` 在 1.1 就測過 round-trip、`f64` 的標準 `Display` 本身就保證輸出可以剛好 parse 回原本的值），所以手刻一個逗號分隔格式就夠，不需要 `serde`。
  - 🟡 如果之後這個格式要版本演進（例如加欄位、要相容舊檔案）或存更複雜的巢狀結構，那時候再評估要不要引入 `serde` + 一個真正的序列化格式（例如 `serde_json`、或自訂 binary），現在不需要就先不加。
- **不重新驗證 `Bar::validate`**：存進來的 `Bar` 在建立時應該已經驗證過（來自 1.5 的 `parse_klines_csv`，或之後 1.7 下載器），儲存層只負責「存進去、讀出來要一樣」，不重複做 1.2 已經做過的合理性檢查。
- **格式錯誤整份回傳錯誤，不跳過壞行**：理由跟 1.5 一樣——回測要吃這份資料，悄悄漏一根 K 線比噴錯誤更危險。
- **測試用 OS 暫存目錄，每個測試各自一個檔名**：避免 cargo test 平行執行時互相覆寫或搶檔案。

## 怎麼驗證

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test -p at-core bar_store
```

`bar_store` 應該看到 9 個測試全過（含一個實際寫檔、讀檔的 round-trip 測試）。全部測試 `cargo test` 目前共 78 個（含 1.1–1.5 與 2.1 的測試）。

## 建議閱讀順序

1. `bar_store.rs` 最上面的說明：格式長什麼樣、為什麼跟 `kline_csv` 是分開的
2. `format_bars` / `parse_bars`：一來一回怎麼對稱
3. 測試 `round_trips_through_a_real_file`：整個流程串起來
4. 測試 `corrupt_file_is_an_error_not_a_panic`、`missing_file_is_an_error_not_a_panic`：壞資料怎麼變成 `Result::Err` 而不是 panic

## 動手試試看

1. 用 `write_bars_file` 存一份有 3 根 K 線的 `Vec<Bar>`，打開存出來的檔案看內容，跟 `format_is_stable_and_predictable` 測試裡斷言的格式比對一下。
2. 把存出來的檔案手動改壞一行（例如刪掉一個逗號），呼叫 `read_bars_file`，看錯誤訊息怎麼指出是第幾行、哪裡不對。

## 下一步銜接

`write_bars_file`/`read_bars_file` 吃的是 `Vec<Bar>`，跟 1.5 的 `parse_klines_csv`/`read_klines_csv` 回傳的型別完全一樣——1.7 下載器從 `data.binance.vision` 下載回來的資料，可以先用 1.5 的方式解析成 `Vec<Bar>`，再用這一步的 `write_bars_file` 存下來，之後回測引擎要重複讀取同一段歷史資料時，直接 `read_bars_file` 讀本機檔案就好，不用每次重新下載、重新解析原始 CSV。
