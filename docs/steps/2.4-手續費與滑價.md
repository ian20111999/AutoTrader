# 2.4 手續費與滑價：讓回測開始花錢

## 做了什麼

改 `crates/core/src/backtest.rs`（加上 `crates/core/src/lib.rs` 的一行匯出）。
2.3 的回測還是免費的：買賣不用付錢、成交價剛好等於開盤價。這一步把兩種真實成本裝上去。

`run_backtest` 的第三個參數從一個 `Fixed`（起始資金）換成一個設定 struct：

```rust
pub struct BacktestConfig {
    pub initial_capital: Fixed,   // 起始資金，必須 > 0
    pub fees: Option<FeeModel>,   // 1.4 的手續費模型；None = 零費率
    pub slippage: Fixed,          // 滑價比例，0.0005 就是 0.05%
}

// 舊的呼叫法
run_backtest(&bars, &mut strategy, fx("10000"))
// 新的呼叫法
run_backtest(&bars, &mut strategy, &BacktestConfig::frictionless(fx("10000")))
```

成交那一段變成四個動作，順序不能換：

```rust
// ① 成交價：開盤價加滑價，買貴賣賤
let fill = bar.open.checked_mul(if want_long { buy_price_mult } else { sell_price_mult })?;

// ② 買：先算「每一顆連手續費的總成本」，才知道這些現金買得起多少
let cost_per_unit = fill.checked_mul(buy_cost_mult)?;   // buy_cost_mult = 1 + 費率
let bought = cash.checked_div(cost_per_unit)?;
let spent = bought.checked_mul(fill)?;                  // 貨款用成交價算
let fee = spent.checked_mul(buy_rate)?;                 // 手續費用貨款算
cash = cash.checked_sub(spent)?.checked_sub(fee)?;

// ③ 賣：收入進來，手續費出去
let proceeds = qty.checked_mul(fill)?;
let fee = proceeds.checked_mul(sell_rate)?;
cash = cash.checked_add(proceeds)?.checked_sub(fee)?;

// ④ 評價還是用「沒加滑價的收盤價」——那是市價，不是你的成交價
```

錯誤型別多了兩個變體，都是在第一根 K 線之前就擋掉的設定錯誤：

| 變體 | 什麼時候出現 |
|---|---|
| `InvalidSlippage` | 滑價 < 0（等於買便宜賣貴，回測會憑空生錢）或 ≥ 1（賣出價會變成 0 或負數）|
| `InvalidFeeRate` | 吃單費率 < 0、≥ 1，或費率相加時溢位 |

`EquityPoint`、`NonPositivePrice`、`Overflow`、`Strategy`、策略實作都沒動。

## 為什麼這樣設計

### 滑價動價格、手續費動金額——兩者不能混

這是這一步最容易寫錯的地方。兩種成本在帳上走的路不一樣：

- **滑價**是「你以為會成交在 100，實際成交在 100.05」。它改的是**價格**，
  所以會連帶改變你買到的**數量**（同樣的錢買得少了）。
- **手續費**是「成交金額的 0.1% 被交易所收走」。它改的是**金額**，不影響成交價，
  是一筆額外從現金扣掉的錢。

如果把手續費也折進價格（例如買在 `100 × 1.001`），數量會算錯，帳上也不會有一筆
可以單獨看的手續費——之後 2.6 想回答「這個策略一年被手續費吃掉多少」就沒得算了。

### 為什麼滑價要「買貴賣賤」

滑價的來源是掛單簿深度不夠、行情在你的單子送到之前就跑了。它的方向不由你決定，
所以回測只能假設它永遠站在對你不利的那一邊：買進成交在 `開盤 × (1 + 滑價)`、
賣出成交在 `開盤 × (1 − 滑價)`。

只在單邊加滑價會低估一半的成本；假設滑價有時對自己有利，那是在回測裡許願。
真實世界裡它偶爾會對你有利，但一個必須拿真錢跑的策略，寧可在紙上低估自己的績效。

### 為什麼評價用的收盤價不加滑價

權益曲線要回答的是「現在把帳戶清算掉值多少錢」的近似值，用的是**市價**。
滑價是「你動手成交那一刻」才發生的事，還沒動手就先把持倉打折，等於每根 K 線
都收一次不存在的費用。加上去的結果是整條權益曲線平移，最大回撤、夏普全部失真。

所以程式裡只有 `fill`（成交價）帶滑價，`bar.close`（評價價）永遠是原始價格。
測試 `slippage_alone_makes_you_buy_dearer` 就是釘這條線的：買在 100.05、評價回 100，
所以買進那一瞬間權益就少了 5——少的是滑價，不是每根都少。

### 為什麼買進要先算「含手續費的單價」

直覺寫法是 `數量 = 現金 ÷ 成交價`，但這樣手續費就付不出來了：
現金 10010、價格 100 買到 100.1 顆，貨款剛好 10010，接著被收 10.01 的手續費，
現金變成 **−10.01**。帳上出現一筆不存在的錢，而且 2.5 加了槓桿之後這個洞會被放大。

所以先算「每買一顆要付多少」= `成交價 × (1 + 費率)`，用它去除現金。
這也是交易所實際的行為：你的下單金額必須含得下手續費，否則會被拒單。
這條規則被 `fee_alone_is_charged_on_the_notional` 釘住（見下面的突變測試）。

### 為什麼費率用 taker、而且只取一次

這一版所有成交都是「下一根開盤直接成交」，也就是**市價單**——市價單一定是吃單（taker）。
掛單（maker）費率比較便宜，但要等有限價單與掛單簿模型才用得到，現在拿 maker 來算
等於偷偷給自己打折。

費率整場不變，所以在迴圈外就把 `buy_rate`、`sell_rate` 取出來（買方、賣方費率可能
不同，所以各取一次）。順手的好處是：費率填錯會在第一筆成交之前就報錯，
而不是跑到第 5000 根才炸。

### 為什麼吃單費率不接受負數

1.4 的 `FeeModel` 允許負費率，因為高等級帳戶的**掛單**確實有返佣。但吃單返佣不存在，
負的吃單費率只會有一個來源：填錯。而且它會讓回測認為「交易本身就能賺錢」，
於是任何高頻亂做的策略都會變成印鈔機——這種錯誤如果沒被擋下來，很可能直接帶著
一個假的好績效上實盤。`invalid_taker_rate_is_rejected` 同時確認
「掛單是負的（返佣）不會被誤擋」。

### 為什麼吃 `BacktestConfig` 而不是多加兩個參數

2.5 還要加合約參數（槓桿、資金費），2.6 可能還要加無風險利率。每次都改簽名等於
每次都要動所有呼叫端。現在包成一個 struct，之後加欄位不必再改簽名一次。

目前唯一的呼叫端是測試，所以這次改動的成本最低——愈晚改愈貴。
`BacktestConfig::frictionless(capital)` 這個建構子讓「零成本對照組」寫起來只要一行。

### 那條零成本迴歸測試為什麼一定要留

成本一打開，「成交當根的權益 = 起始資金」這個恆等式就不成立了（買進的瞬間就先虧掉
滑價與手續費）。恆等式沒了，就很難分辨「數字變了是因為真的扣了成本」還是
「記帳邏輯本身壞了」。

`zero_cost_reproduces_the_2_3_numbers` 把 2.3 的資料與答案原封不動搬過來：
零費率、零滑價時它必須算出 `[10000, 20000, 15000]`，一個數字都不能差。
加上成本之後同一組資料的權益必須**變差**（第二段斷言）——如果兩者相同，
就表示成本根本沒被算進去。

### 既有測試怎麼處理

2.3 的 13 個測試一個都沒刪、斷言的數字一個都沒改，只把第三個參數換成
`&frictionless("10000")`。這是刻意的：它們就是這一步的迴歸網。
新增 7 個測試（`backtest::tests` 從 13 個變 20 個）。

### 手算對照：價格完全不動，成本自己吃掉 30

測試 `a_round_trip_on_a_flat_market_costs_exactly_the_four_charges`。
四根 K 線的開盤與收盤都是 **100**（價格從頭到尾不動），吃單費率 **0.1%**、
滑價 **0.05%**、起始資金 **10015.005**（挑這個數字是為了讓數量剛好 100 顆，
不用跟四捨五入的零頭糾纏），策略第一根說做多、之後空手。

| K 線 | 這根做的事 | 手算 | 權益 |
|---|---|---|---|
| 0 | 收盤說做多 → 只記著 | — | 10015.005 |
| 1 | 買：成交價 `100 × 1.0005 = 100.05`；每顆總成本 `100.05 × 1.001 = 100.15005`；數量 `10015.005 ÷ 100.15005 = 100`；貨款 `100 × 100.05 = 10005`、手續費 `10005 × 0.001 = 10.005` → 現金 0 | `0 + 100 × 100` | 10000 |
| 2 | 賣：成交價 `100 × 0.9995 = 99.95`；收入 `100 × 99.95 = 9995`、手續費 `9995 × 0.001 = 9.995` → 現金 9985.005 | — | 9985.005 |
| 3 | 空手 | — | 9985.005 |

來回總成本 `10015.005 − 9985.005 = 30`，四筆拆開剛好對得起來：

| 費用 | 算式 | 金額 |
|---|---|---|
| 買進滑價 | 10000 × 0.05% | 5 |
| 買進手續費 | 10005 × 0.1% | 10.005 |
| 賣出滑價 | 10000 × 0.05% | 5 |
| 賣出手續費 | 9995 × 0.1% | 9.995 |
| | | **30** |

**價格一動都沒動，一趟來回就先虧 0.3%。** 這就是為什麼「不含成本的回測是自欺」：
一個每天進出一次的策略，光成本一年就要 0.3% × 250 ≈ 75%。

另外兩個單獨看一種成本的測試（數字一樣是挑好的，讓數量剛好 100 顆）：

| 測試 | 設定 | 起始 → 成交當根權益 | 少掉的錢 |
|---|---|---|---|
| `slippage_alone_makes_you_buy_dearer` | 只有滑價 0.05% | 10005 → 10000 | 5 = 10000 × 0.05% |
| `fee_alone_is_charged_on_the_notional` | 只有吃單 0.1% | 10010 → 10000 | 10 = 10000 × 0.1% |

### 突變測試：確認新測試真的抓得到錯

刻意把程式改壞四次，看測試會不會變紅（改完記得改回來）。實測結果：

| 故意改壞 | 實測結果 | 抓到它的測試 |
|---|---|---|
| 賣出也用買進的滑價乘數（買貴**賣貴**）| `9994.995`，應該是 `9985.005` | `a_round_trip_...` |
| 買進用 `cash ÷ fill` 而不是 `cash ÷ cost_per_unit` | `9999.99`，應該是 `10000`（現金被扣成 −10.01）| `a_round_trip_...`、`fee_alone_...` |
| 賣出忘記扣手續費 | `9995`，應該是 `9985.005` | `a_round_trip_...` |
| 評價用的收盤價也乘上滑價 | `9995`，應該是 `10000` | 三個成本測試 |

四次都被抓到。第二個特別值得看：它是唯一一個會讓**現金變成負數**的錯，
而且錯的量剛好等於手續費。

   對照上面的手算表格。

## 動手試試看

1. 把 `crates/core/src/backtest.rs` 裡買進的
   `let bought = cash.checked_div(cost_per_unit)?` 改成 `.checked_div(fill)?`，
   跑 `cargo test -p at-core backtest`。
   `fee_alone_is_charged_on_the_notional` 會變成 `9999.99`（應該是 `10000`）——
   那 0.01 的缺口就是「買了付不出手續費」，帳上的現金是 −10.01。
   **一個回測如果允許現金變負數，它就是在偷偷加槓桿。**
2. 把賣出的 `sell_price_mult` 改成 `buy_price_mult`（變成買貴賣貴），跑測試：
   `a_round_trip_...` 會變成 `9994.995`。看得出來嗎？賣出多拿了 10 左右，
   因為滑價站到了對你有利的那一邊——這就是最常見的「回測比實盤好」的來源。
3. 把評價那一行 `let price = bar.close;` 乘上 `sell_price_mult`，跑測試：
   三個成本測試一起紅。感受一下「每根 K 線都偷收一次滑價」會讓整條曲線平移多少。
4. 拿 `SmaCross` 之類的真策略跑同一份 K 線兩次，一次 `BacktestConfig::frictionless(...)`、
   一次 `BacktestConfig { initial_capital, fees: Some(FeeModel::spot_vip0()), slippage: fx("0.0005") }`，
   比較最後一點的權益。進出愈頻繁的參數，兩者差距愈大——
   這就是為什麼參數最佳化一定要含成本，否則會選出一組「手續費繳最多」的參數。
5. 把滑價設成 `0.01`（1%，流動性很差的小幣或大單的實際狀況），
   看同一個策略還剩多少獲利。很多在紙上很漂亮的短線策略會直接翻負。
6. 試著把滑價設成 `-0.0001`，確認拿到 `InvalidSlippage` 而不是一條漂亮的權益曲線。

## 2.5 怎麼接

2.5 要做合約：做空、槓桿、資金費。和這一步的關係：

- **手續費的計算基礎不變，但基數會變大。**手續費一直是「名目成交金額 × 費率」，
  而槓桿放大的就是名目金額：3 倍槓桿的同一筆資金，手續費也是 3 倍。
  所以 `spent`／`proceeds` 要換成「名目金額」之後，`× buy_rate` 這段不用改。
  費率本身要從 `FeeModel::spot_vip0()` 換成 `FeeModel::futures_vip0()`
  （吃單 0.05%，比現貨便宜一半）。
- **做空要決定滑價的方向。**現在的 `want_long` 只有兩個狀態，滑價的方向直接跟著它。
  做空之後「開空」是賣出（賣賤）、「平空」是買進（買貴），所以判斷條件要從
  「想不想做多」換成「這筆成交是買還是賣」——順手也讓 `Side` 用得更名正言順。
- **`BacktestConfig` 是槓桿與資金費率的落腳處**，簽名不用再改。
- 零成本迴歸測試要繼續留著，並且再加一條「槓桿 1 倍 + 只做多 = 2.4 的數字」
  的迴歸測試：同樣的理由，合約的記帳要能退化回現貨才證明沒寫壞。
