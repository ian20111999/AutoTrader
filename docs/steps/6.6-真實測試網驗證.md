# 6.6 真實測試網端到端驗證

用使用者自己在 Binance 申請的測試網金鑰，把 6.1-6.5 做的東西真的接上 Binance、跑一次
完整的「策略算出目標部位 → 風控閘門 → 送出市價單 → 等交易所回報 → 更新本地帳本」。

## 過程中發現並修正的事：Binance 把測試網遷移了

第一次用使用者申請的金鑰測試時，不管金鑰對不對、順序怎麼換，一律收到 Binance 回的

```json
{"code":-2015,"msg":"Invalid API-key, IP, or permissions for action."}
```

查證後確認：Binance 已經把現貨測試網從 6.1-6.5 當時寫死的 `testnet.binance.vision`
遷移到新的「Demo Trading」服務 `demo-api.binance.com`，舊網址的簽名端點一律回這個錯誤，
跟金鑰本身對不對無關——這是 Binance 那邊的基礎設施變動，不是這個專案的錯誤，但確實是
寫 6.1-6.5 時還沒發生、沒辦法事先知道的事。

修正方式：只改 `crates/binance-client/src/testnet.rs` 的 `TESTNET_BASE_URL` 這一個常數，
下單路徑、簽名機制、回應格式都沒變。這個常數改錯的代價很高（簽名過的下單請求會送到
別的地方），所以查證了三個獨立來源才改：使用者自己 Binance 帳戶頁面上的官方文件連結、
Binance 官方 `demo-mode/general-info` 文件逐字確認 base URL、以及 TLS 憑證（確認
`subject=O=Binance Holdings Limited, CN=*.binance.com`，DigiCert 簽發，不是誰都能
偽造的憑證）。

順便修掉一個被自動安全審查抓到的副作用：既有測試 `signed_url_points_only_at_the_testnet_host`
用 `!url.contains("api.binance.com")` 擋正式環境，但新測試網網址 `demo-api.binance.com`
本身就包含 `api.binance.com` 這個子字串，寬鬆的子字串比對在這裡會誤判。改成切出真正的
host 再精確比對（`host != "api.binance.com"`），不是放寬這個安全網，而是讓它變得更精確。

## 第一關：單純下單＋查詢（`at-binance` 的 `#[ignore]` 測試）

```
test testnet::tests::place_and_query_market_order_against_real_testnet ... ok
```

對 `BTCUSDT` 下了一張 0.001 BTC 的市價買單，Binance 回報立刻成交，再查詢一次訂單狀態
確認資料一致。這一關只驗證「簽名→送單→解析回應」這條路徑本身是通的，不碰風控或帳本。

## 第二關：完整的策略執行鏈（`at-testnet-trading` 的 `#[ignore]` 測試）

```
下單結果：Filled(FillReport { order_id: 69295051080, side: Buy, requested_qty: Fixed(0.00118),
  executed_qty: Fixed(0.00118), quote_qty: Fixed(99.5518918), fee: Fixed(0.09955189),
  status: Filled })
收盤 1790835420000：現金 900.34855631、部位 0.00118、權益 999.90043631、手續費合計 0.09955189
test tests::trades_against_the_real_testnet ... ok
```

接上真實的 `BTCUSDT` 1 分鐘即時行情，等到一根真的收盤，策略（固定目標部位 10% 多單）
被呼叫、算出要買的數量、過風控閘門（每日虧損上限 50、單筆上限 200 USDT）、真的送出市價單
到 Demo Trading、拿到終態回報、更新本地帳本。

手動核對帳本算得對不對：

- 起始現金 1000，買進花掉報價金額 99.5518918、手續費 0.09955189（= 99.5518918 × 0.1%
  吃單費率，跟 `FeeModel::spot_vip0()` 設定一致）：
  `1000 − 99.5518918 − 0.09955189 = 900.34855631` ——跟印出來的現金完全一致。
- 權益 = 現金 + 部位 × 收盤價：`999.90043631 − 900.34855631 = 99.5518800`，除以部位
  `0.00118` 約等於 `84366`，跟成交均價（`99.5518918 ÷ 0.00118 ≈ 84366.86`）一致，合理。

這證實了 6.4 文件裡記載的手續費估算設計（用 4.3 同步到的帳戶費率算，不信任交易所回報）
算出來的數字，跟真實送單花掉的報價金額對得上。

## 範圍：這次驗證了什麼、沒驗證什麼

驗證過的：下單簽名、送單、查單、風控閘門真的會擋/放行、本地帳本的現金與手續費計算、
一鍵停止與停止的機制（跨模型審查時已驗證過程式碼邏輯，這次沒有特別去真的按過一鍵停止，
因為要抓準真的送單的那個時間點手動按太難重現，邏輯正確性已經由 6.4 的單元測試與 Codex
的審查涵蓋）。

沒驗證的：撤單（市價單立刻成交，天生不會有可撤的單，6.2 文件已經說明過這件事）、部分成交
的真實情境（這次剛好是完全成交）、`app` 桌面介面本身的真實連線（6.5 的頁面邏輯已經過
QA 驗證，這次只驗證底層 Rust crate，沒有實際打開 App 點按鈕）。

## 怎麼重現

```bash
cargo test -p at-binance -- --ignored --nocapture place_and_query_market_order_against_real_testnet
cargo test -p at-testnet-trading -- --ignored --nocapture trades_against_the_real_testnet
```

需要先把 Demo Trading 的 API Key／Secret 存進 Keychain（`com.autotrader.app.binance-testnet-api-key`
／`-api-secret`，account `autotrader`）——可以用 App 的「測試網交易」頁面存，或手動用
`security add-generic-password` 存。第二個測試會等到下一根真實的 1 分鐘 K 線收盤才會
真的送單，最多等 3 分鐘。
