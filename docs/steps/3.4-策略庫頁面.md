# 3.4 策略庫頁面

## 做了什麼

把策略庫分頁裡陽春的 `<BuiltinStrategies />`（3.2 橋接驗證用的純清單）換成正式版面 `Strategies.tsx`：

- 資料來源不變，一樣呼叫 Tauri command `list_builtin_strategies`，型別沿用 `strategyTypes.ts`。
- 畫成卡片格線（`.strategy-grid` / `.strategy-card`），每張卡片顯示策略名稱＋參數摘要（例如「快線週期10、慢線週期50」）。
- 卡片可以點擊選中（`aria-pressed` + 高亮邊框/背景），純前端的 UI 狀態，不影響任何資料。
- 讀取中／讀取失敗沿用原本的文字狀態，`role="alert"` 不變。

附帶修正：自動 commit 安全審查抓到 3.3 在 `index.html` 加的 Google Fonts `<link>` 會讓桌面 App 每次啟動都連線
`fonts.googleapis.com`（supply-chain + privacy 疑慮）。改用 `@fontsource/ibm-plex-sans`、`@fontsource/noto-sans-tc`、
`@fontsource/jetbrains-mono` 把字體檔案打包進 App，在 `main.tsx` 用 `import "@fontsource/.../400.css"` 這類寫法載入，
`index.html` 的 `<link rel="preconnect">` 和 Google Fonts stylesheet 都拿掉了。

## 為什麼要這樣做

### 卡片版面 vs 設計稿

設計稿 `Strategies.dc.html` 畫的是完整產品的策略庫：分「我的策略／內建範本」兩個頁籤、市場與狀態篩選、
每張卡片還有回測年化／最大回撤／近 30 天實際報酬、權益曲線縮圖、即時交易狀態徽章（實盤中／模擬中／測試網中）、
以及「調參數／回測/模擬/部署」四個操作按鈕，下方還有一個「從範本開始」的 9 個範本 + 自訂 WASM 匯入的區塊。

這個 App 現在只有 `list_builtin_strategies` 這一個 command，只回傳「4 個內建策略的 id/name/params」，
沒有回測結果、沒有實盤/模擬帳戶、沒有範本分類、也不支援自訂 WASM 策略。如果照設計稿把那些欄位和按鈕都做出來，
會全部是假資料或假按鈕，違反公司規則「未實作功能必須 disabled + 說明文字，不能讓用戶點了沒反應」。

所以這一步只搬設計稿的**視覺語言**（深色卡片、`#12161D` 背景、`#242B36` 邊框、10px 圓角、間距、字級），
內容砍到現在資料撐得住的範圍：名稱 + 參數摘要 + 選中狀態。這跟 3.3 `TopBar.tsx` 砍掉帳戶權益/今日損益欄位
是同一個判斷。

### 3.4 / 3.5 範圍界線

設計稿卡片上的「調參數」按鈕會連去 `StrategyEditor.dc.html`——也就是 ROADMAP 3.5（策略調參頁面）。
3.5 還沒做，這一步選擇**完全不放這顆按鈕**，而不是放一個 disabled 的「即將推出」按鈕：
因為點下去之後唯一該發生的事（打開調參表單）本來就還不存在，disabled 按鈕在這裡除了佔位沒有其他資訊量，
不如等 3.5 真的把調參頁面做出來，按鈕跟功能一起出現。

卡片的「選中」狀態則保留：這是一個現在就能完整運作的互動（點擊→高亮），不是預告未來功能，
所以不算公司規則講的「假按鈕」。

### 字體改本地打包

Fontsource 套件把 Google Fonts 的字重拆成一個個 `@fontsource/<font>/<weight>.css`，每個檔案裡的
`@font-face` 都指向套件內的 `./files/*.woff2`，build 出來會被 Vite 當成本機靜態資源打包進 `dist/assets/`，
執行期完全不用連網路。

## 怎麼驗證

```bash
cd app
npm test        # Vitest：8 個測試全過
npm run lint     # ESLint 零錯誤
npm run build    # tsc + vite build 成功
```

離線驗證（用 Playwright 開 `npm run dev` 的頁面觀察 network log）：

1. `browser_network_requests` 列出所有請求，全部是 `http://localhost:<port>/...`，沒有任何一筆是
   `fonts.googleapis.com` 或 `fonts.gstatic.com`。
2. `document.fonts` 檢查：`IBM Plex Sans`／`Noto Sans TC`／`JetBrains Mono` 各字重都有 `loaded` 狀態，
   `<h1>` 的 `computedStyle.fontFamily` 確實是 `"IBM Plex Sans", "Noto Sans TC", sans-serif`。
3. 因為 `invoke` 需要 Tauri runtime、純瀏覽器沒有，另外在頁面上手動掛一個假的
   `window.__TAURI_INTERNALS__.invoke` 回傳 4 個內建策略的 mock 資料，重新掛載策略庫分頁後截圖，
   確認四張卡片版面、字體、選中狀態（點擊後邊框變金色高亮）都如預期渲染，中文字型正常顯示（沒有退回系統預設字）。

根目錄額外跑過 `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`，
確認 195+10+3+1 個測試數量不變（這次改動完全沒碰 `crates/` 或 `app/src-tauri`）。

## 建議閱讀順序

1. `app/src/strategyTypes.ts`：前後端共用的型別（不用改，直接沿用）
2. `app/src/Strategies.tsx`：新的策略庫元件，看 `paramSummary` 怎麼把 `params` 陣列摘要成一行字
3. `app/src/Strategies.test.tsx`：四個測試——四張卡片渲染、資料變動畫面跟著變、點擊選中、錯誤訊息
4. `app/src/App.css` 的「策略庫」段落：`.strategy-grid` / `.strategy-card` 怎麼對應設計稿的顏色與間距
5. `app/src/main.tsx`：字體改成 `import "@fontsource/..."` 本地載入

## 動手試試看

1. 把電腦的 Wi-Fi 關掉（或用瀏覽器開發者工具封鎖 `fonts.googleapis.com`），跑 `npm run dev` 打開 App，
   確認中文和英文字都正常顯示、不會變成系統預設字體。
2. 在 `Strategies.tsx` 的 `paramSummary` 裡把 join 的分隔符從 `、` 改成 `, `，跑 `npm test` 看哪個測試會失敗、
   訊息長什麼樣，再改回來。
