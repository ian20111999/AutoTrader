# 6.5 桌面 App「測試網交易」頁面＋風控設定

把 6.4 已經審查過的交易邏輯（`at-testnet-trading`）接成使用者看得到、用得到的頁面。這是整個
專案第一次在 UI 上能觸發真實送單（僅限測試網）。6.4 的交易/風控邏輯本身在這一步完全沒有被
動到。

## 做了什麼

Rust（`app/src-tauri`）：

- `testnet_settings.rs`（新）：測試網專用 Keychain 金鑰管理（`save_testnet_credentials`／
  `testnet_credentials_status`／`clear_testnet_credentials`），架構照抄 4.6 的
  `settings.rs`，但用 6.1 的測試網專用 service name（`com.autotrader.app.binance-testnet-api-key`
  /`-api-secret`），跟 4.1/4.6 正式環境唯讀金鑰完全分開。
- `testnet_trading.rs`（新）：`start_testnet_trading`／`stop_testnet_trading`／
  `set_testnet_kill_switch`／`testnet_trading_status` 四個 command。`start` 的流程：讀測試網
  金鑰建立 `BinanceTestnetClient` → 用正式環境唯讀金鑰透過 `at-account-sync` 同步真實手續費率
  與下單規則（4.3/4.4 第一次被接進 App，之前只有 crate 自己的測試用過）→ 組
  `RiskLimits`／`TestnetConfig` → 接上 4.5 即時行情 → 呼叫 `at_testnet_trading::spawn`。
- `crates/binance-client/src/testnet.rs`：唯一的改動是把測試網 Keychain 的三個常數從私有
  改成 `pub`，讓 `testnet_settings.rs` 能直接引用同一份字串，不用在兩邊各寫一次（改一邊忘改
  一邊的風險）。邏輯本身一行都沒動。

前端（`app/src`）：

- `TestnetTrading.tsx`（新）：版面大量重用 `PaperTrading.tsx`／`Settings.tsx` 既有的結構與
  CSS class。金鑰輸入區塊直接嵌在這個頁面裡（這組金鑰只有這裡會用到，不跳頁去 4.6 的設定頁）。

## 為什麼這樣設計

### 一鍵停止跟停止用不同的橋接手法，而不是照搬 5.4

5.4 的 `PaperTradingHandle` 把整個 handle 搬進背景執行緒，所以「停止」要先在 `spawn` 之前
另外跟行情連線要一份停止旗標複本，才能在其他 command 裡喊停。`TestnetTradingHandle` 的
`stop`／`set_kill_switch`／`kill_switch` 都只要 `&self`，所以這次把整個 handle 留在 Tauri
state 裡（`Mutex<Inner>`），不搬進執行緒；背景執行緒改成每次只 `recv_timeout(200ms)` 短暫
持鎖一次（沿用 crate 內部 `STOP_CHECK_INTERVAL` 的 200ms 慣例），而不是整段迭代佔住鎖——
否則「停止」／「一鍵停止」這兩個 command 想拿鎖時會被卡到下一根 K 線收盤才搶得到。好處是
完全不用碰已經審查過的 `at_testnet_trading`，也不用幫它新增任何 public getter。

### 一鍵停止與停止在 UI 上刻意用文字說清楚差異，不只是顏色不同

6.4 的設計就是這兩個是獨立開關（一鍵停止只擋送單，行情跟策略照常跑；停止才會連行情一起
收工），UI 文案直接寫白話：「一鍵停止：暫停送出新訂單，行情與帳本繼續更新，隨時可以恢復。」
vs「停止：整條交易連線收工，連行情也會一併斷線。」——避免使用者以為兩顆按鈕做同一件事。

### 手續費／下單規則用正式環境同步，不用測試網

延續 6.4 的既定設計：測試網沙盒回報的手續費不可信（很可能是 0），所以用 4.3/4.4 已經驗證過
的正式環境唯讀連線（`BinanceClient::from_keychain()`）同步真實帳戶費率與下單規則，只有下單
本身走測試網。
