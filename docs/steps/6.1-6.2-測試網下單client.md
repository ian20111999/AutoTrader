# 6.1-6.2 Testnet 金鑰獨立存放＋下單 client

這是整個 repo 第一次出現「送出訂單」的程式碼路徑。使用者已明確同意跨過這條安全線，
範圍只限測試網（`testnet.binance.vision`），正式環境下單是第 7 步，需要另一次明確同意。
詳細計畫見 `docs/plans/2026-10-01-testnet-trading.md`。

## 做了什麼

`crates/binance-client/src/testnet.rs`（新模組 `at_binance::testnet`）：

- `BinanceTestnetClient`：只有 `api_key`、`api_secret` 兩個欄位，**沒有 `base_url` 欄位**。
  網址寫死在模組層級常數 `TESTNET_BASE_URL`，所有方法都經過唯一的 `signed_url()` 組網址，
  型別上就不可能指向正式環境——不是「程式碼審查時小心一點」的約定，是編譯期的事實。
- `from_keychain()`：讀 Keychain 的 `com.autotrader.app.binance-testnet-api-key` /
  `-api-secret`（帳號 `autotrader`），跟 4.1/4.6 正式環境唯讀金鑰的 service name 完全分開，
  避免兩組憑證互相覆蓋或讀錯。
- `place_market_order`（市價單）、`query_order`（查詢狀態）、`cancel_order`（撤單）三個方法，
  簽名沿用既有 `crate::sign`/`build_signed_query`（POST/DELETE 都把參數放進 query string、
  body 留空，簽名方式跟既有 GET 完全一樣）。
- `OrderStatus`：涵蓋官方文件 `enums.md` 列出的全部九種狀態（含文件標示「目前沒用到」的
  `PENDING_CANCEL`），遇到不認得的字串回錯誤而不是用別的狀態硬套。
- `OrderResponse`：只解析三個端點共用的欄位；刻意不解析 `FULL` 回應才有的 `fills` 明細——
  那是 6.4 寫帳本時才需要的東西，現在沒有呼叫端會用。

## 為什麼這樣設計

### 不共用 `BinanceClient` 的 `base_url`

既有 `BinanceClient` 的 `base_url` 是可變欄位，日後只要有人改錯一個預設值或多開一個建構子，
就有可能讓下單程式碼連到正式環境。送單是這個專案第一次出現真的會動用資產的程式碼路徑，值得
為它新開一個欄位集合更小的型別，把「不可能連到正式環境」做成型別系統保證。

### 四個官方範例全部離線驗證過

New Order（RESULT／FULL）、Query Order、Cancel Order 四個官方文件範例都當成單元測試的已知
答案。跨模型驗證（Claude QA）過程中發現 Query Order 的範例原本有 `origQty` 跟三個時間戳被
改過（內部仍自洽，測試邏輯本身沒錯，但不是文件宣稱的「逐字複製」），已經修正成跟官方文件
完全一致的值，避免之後有人誤以為那是精確的官方資料來源。

## 怎麼驗證

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
```

`at-binance` 新增 21 個測試全線通過（含 `place_and_query_market_order_against_real_testnet`
這個 `#[ignore]` 的真實測試網端到端測試，需要使用者自己申請 testnet.binance.vision 金鑰才能
跑——6.6 會補這一塊）。整個 workspace 其餘 crate 的既有測試零迴歸。

## 建議閱讀順序

1. `crates/binance-client/src/testnet.rs` 開頭的模組說明（doc comment），理解為什麼要獨立
   一個 client 型別而不是擴充既有的 `BinanceClient`。
2. `BinanceTestnetClient::signed_url`：唯一的網址組裝入口。
3. `place_market_order`/`query_order`/`cancel_order`：三個方法都呼叫同一個 `signed_url`。

## 動手試試看

1. 試著在 `BinanceTestnetClient` 加一個方法想要自己指定 base URL——會發現根本沒有欄位可以
   傳進去，型別上就擋住了。
2. 如果你已經在 testnet.binance.vision 申請了 API 金鑰，存進 Keychain（service name 見上面）
   後跑 `cargo test -p at-binance -- --ignored --nocapture`，看能不能真的在測試網下一筆市價單。
