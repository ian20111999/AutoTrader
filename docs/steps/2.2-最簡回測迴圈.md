# 2.2 最簡回測迴圈 `run_backtest`

## 做了什麼

新增 `crates/core/src/backtest.rs`，只有一個函式與兩個型別：

```rust
pub fn run_backtest(
    bars: &[Bar],
    strategy: &mut dyn Strategy,
    initial_capital: Fixed,
) -> Result<Vec<EquityPoint>, BacktestError>

pub struct EquityPoint { pub open_time: i64, pub equity: Fixed }

pub enum BacktestError { NonPositiveCapital, NonPositivePrice { index }, Overflow { index } }
```

迴圈每根 K 線做四件事：

1. 檢查收盤價是正數（外部 CSV 來的資料不能信）。
2. 呼叫 `strategy.on_bar(bar)` 拿目標部位。
3. 目標 > 0 且目前空手 → 把**全部現金**換成部位；目標 ≤ 0 且目前有部位 → 全部賣回現金。
4. 記一筆 `EquityPoint`：這根收盤時的 `現金 + 持倉 × 收盤價`。

順帶在 `Fixed` 上補了 `checked_div`（金額 ÷ 價格 = 數量）。`Fixed` 之前只有加減乘，
沒有除法就算不出「一萬塊能買幾顆」，也就畫不出權益曲線。做法和 `checked_mul` 對稱：
中間用 `i128`、第 9 位四捨五入、除以 0 回 `None`。2.4 的滑價百分比、2.6 的報酬率與
最大回撤都會用到它。

這一步**沒有**手續費、沒有滑價、沒有做空、沒有槓桿、沒有資金費、沒有績效指標，
也沒有「下一根開盤成交」——分別是 2.4、2.5、2.6、2.3 的事。

## 為什麼這樣設計

### 成交時點：這一版故意用「收盤價成交」，而且它是錯的

專案總則寫著「訊號在 K 線收盤產生，下一根開盤成交」，但 ROADMAP 把
「下一根開盤成交」排在 2.3。兩種做法都想過：

| 做法 | 取捨 |
|---|---|
| (a) 2.2 直接做對：訊號收盤、下一根開盤成交 | 數字一開始就可信，但 2.3 會變成空的一步，而且「成交模型」與「記帳骨架」兩件事一起上，出錯時分不清是哪一邊 |
| **(b) 2.2 先用收盤價成交（採用）** | 這一版的數字偏樂觀、不可信；換來的是 2.3 只改一個地方，而且改完前後的數字差距就是「偷看未來值多少錢」的實測 |

採用 (b)，理由是**一步只改一件事**：2.2 要釘的是「餵 K 線 → 記帳 → 權益曲線」這條骨架
（買賣怎麼記、零頭去哪、溢位怎麼處理、曲線長什麼樣）。把成交時點一起塞進來，
之後看到數字不對就得同時懷疑兩件事。

代價要講清楚：**收盤價成交等於看完收盤價才決定、卻還拿得到那個價格**，
這是回測最典型的偷看未來（look-ahead bias），也是實測績效比回測差的頭號原因。
所以這一版的權益曲線**不可以用來判斷策略能不能賺錢**，只能用來確認記帳是對的。
這句話同時寫在 `backtest.rs` 最上面，免得之後有人拿它的數字當結論。

### 2.3 要改什麼（已經對好介面了）

迴圈現在是「先用這根的收盤價成交、再用這根的收盤價評價」。2.3 只要把這兩件事分開：

- 把策略回傳的目標**存起來**，不當場成交。
- 下一根進來時，先用 `bar.open` 成交上一根留下的目標，再用 `bar.close` 評價。

也就是「成交價從 `bar.close` 換成 `bar[下一根].open`」加上一個 `pending_target` 變數，
`EquityPoint`、錯誤型別、對外簽名都不用動。2.4 再往成交那一段加手續費與滑價，
2.5 把 `qty` 允許負值（做空）、把 `> 0 就全押` 換成按比例配置（槓桿）。

### 帳上記「現金 + 數量」，不是記「報酬率」

另一種常見寫法是每根算報酬率再連乘：`權益 *= 1 + 部位 × 漲跌幅`。它更短，但：

- 2.4 的手續費是**金額**（成交額 × 費率），記報酬率就得把金額硬換回比例。
- 2.5 做空與槓桿在「數量可以是負的、可以大於現金」下是自然的延伸，報酬率寫法要另外處理保證金。
- 現金／數量兩個變數本來就是實盤帳戶的樣子，四種模式共用同一套心智模型。

所以即使這一步只有「滿倉或空手」兩個狀態，也先用現金 + 數量記帳。

### 零頭留在現金裡

`10000 ÷ 3 = 3333.33333333`（`Fixed` 只有 8 位小數），買進花掉 `9999.99999999`，
剩下的 `0.00000001` **留在現金**而不是丟掉。差別只有一億分之一，但這樣
「成交當根的權益 = 起始資金」這條恆等式才會精確成立——一旦允許記帳憑空少錢，
之後 2.4 加手續費時就分不清少掉的錢是手續費還是四捨五入。
測試 `rounding_leftover_stays_in_cash` 就是在釘這條。

### 只做多、二元部位

目標部位 `> 0` 一律當成「全部資金做多」，`≤ 0` 一律當成空手：
半倉、兩倍槓桿、做空這一版都不處理（`TargetPosition` 介面已經表達得出來，
只是迴圈還沒實作）。做空訊號現在會被當成空手，測試
`short_target_is_treated_as_flat_for_now` 把這個暫時行為釘住，
2.5 實作做空時那個測試就會被改掉——它的存在是為了讓「還沒做」變成看得見的事實，
而不是安靜地把做空訊號吃掉。

### 什麼算錯誤、什麼不算

- **空的 `bars`**：不是錯誤，回傳空曲線。沒資料就是沒結果，不需要呼叫端處理例外。
- **起始資金 ≤ 0**：錯誤。介面之後會讓人自己填金額，填 0 應該當場講，不該跑出一條全 0 的曲線。
- **收盤價 ≤ 0**：錯誤，附出錯的第幾根。`Bar::validate()` 會擋掉，但回測不該假設呼叫端一定驗過。
- **數值溢位**：錯誤，附第幾根。全部用 `checked_*`，極端輸入回錯誤而不是 panic
  （測試 `extreme_numbers_return_an_error_instead_of_panicking`）。

### 沒用到 `warmup_bars()`

策略在暖機期會自己回空手，權益自然打平，所以迴圈不需要為它做事。
「把暖機期排除在績效統計外」是 2.6 算年化與夏普時才要處理的，現在做就是猜。

## 怎麼驗證

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
```

`at-core` 共 94 個測試通過，其中 12 個是 `backtest::tests::*`、3 個是新增的
`fixed::tests::divide_*`（既有的 `overflow_returns_none_instead_of_wrong_answer`
也補了一條除法溢位）。

```bash
cargo test -p at-core backtest
```

手算對照（測試 `all_in_long_compounds_price_moves`）：起始 10000，價格 100 → 110 → 121。

| K 線 | 收盤價 | 動作 | 權益 | 為什麼 |
|---|---|---|---|---|
| 0 | 100 | 用 10000 買 100 顆 | 10000 | 買進當根還沒有損益 |
| 1 | 110 | 續抱 | 11000 | `100 × 110`，也就是 10000 × 1.1 |
| 2 | 121 | 續抱 | 12100 | `100 × 121`，也就是 10000 × 1.1 × 1.1 |

另外兩個值得看的數字：

- `the_exit_bar_own_move_still_counts`：100 → 110 → 50，第三根決定空手。
  權益是 `11000 → 5000`，**不是** 11000——因為部位一直抱到那根收盤才賣，
  那根自己的跌幅照算。這就是收盤價成交模型最容易誤解的地方。
- `flat_strategy_keeps_equity_flat`：永遠空手的策略，權益三根都是 10000。
  這條先確認「不交易就不會有損益」，不然後面任何數字都不用看。

## 建議閱讀順序

1. `backtest.rs` 最上面的模組說明——特別是「成交價刻意是樂觀的」那一段。
2. `run_backtest` 的迴圈本體（約 40 行），照著「檢查價格 → 問策略 → 買賣 → 記一點」四步看。
3. `Fixed::checked_div`，和它上面的 `checked_mul` 對照著看，兩者的四捨五入是同一套。
4. 測試 `all_in_long_compounds_price_moves` 與 `the_exit_bar_own_move_still_counts`，
   兩個一起看才會懂「收盤成交」的含意。
5. `rounding_leftover_stays_in_cash`：為什麼零頭不能丟。

## 動手試試看

1. 看一下測試的 `bars()` 輔助函式：它造出來的 K 線 `open == high == low == close`
   （這一版只用得到收盤價，所以刻意這樣簡化）。這代表**現有測試分辨不出**
   「收盤成交」和「下一根開盤成交」的差別。自己造兩根 `open = 100 / close = 120`、
   `open = 130 / close = 110` 的 K 線，手算兩種模型各會得到什麼權益——
   算出來的那個差距，就是 2.3 第一個要寫的測試。
2. 把零頭那行 `cash = cash.checked_sub(spent)?;` 改成 `cash = Fixed::ZERO;`，
   跑 `cargo test`。`rounding_leftover_stays_in_cash` 會抓到差一億分之一的偏差，
   看它的錯誤訊息，感受一下「安靜地少一點錢」在測試裡長什麼樣。
3. 自己寫一個「跌了就買、漲了就賣」的假策略餵進去，先猜權益曲線再跑。
   猜錯的話，八成是忘記「決定的那根本身也算在裡面」。
4. 把起始資金改成 `fx("0")`，確認拿到的是 `NonPositiveCapital` 而不是一條全 0 的曲線。
