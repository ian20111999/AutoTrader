# 2.5 合約：做空、槓桿、資金費

## 做了什麼

只改 `crates/core/src/backtest.rs` 一個檔案（`fees.rs`、`strategy.rs`、策略實作都沒動）。
2.4 的回測只會做多、滿倉或空手；這一步讓它變成 U 本位永續合約的記帳：
**倉位可以是負的（做空）、名目金額可以大於權益（槓桿）、持倉要付資金費、
虧太多會被強制平倉。**

帳本的形狀完全沒變，還是「現金 + 倉位數量」，只是兩個數字都可以是負的：

| 狀態 | 現金 | 數量 | 權益 `現金 + 數量 × 價格` |
|---|---|---|---|
| 空手 | 10000 | 0 | 10000 |
| 1 倍做多 | 0 | +100 @100 | 10000 |
| 1 倍做空 | 20000 | −100 @100 | 10000 |
| 2 倍做多 | −10000 | +200 @100 | 10000 |

做空就是數量變負（先賣後買，現金先變多）；槓桿就是現金變負（跟交易所借錢）。
這一條式子等價於交易所的「錢包餘額 + 未實現損益」，好處是不必另外記進場均價。

`BacktestConfig` 多了兩個欄位（2.4 已經先把設定包成 struct，所以簽名沒再改一次）：

```rust
pub struct BacktestConfig {
    pub initial_capital: Fixed,
    pub fees: Option<FeeModel>,
    pub slippage: Fixed,
    pub funding_rate: Fixed,                        // 新增：每 8 小時的資金費率，0 = 關掉
    pub maintenance_margin_rate: Option<Fixed>,     // 新增：維持保證金率，None = 不模擬爆倉
}
```

成交那一段從「買進 / 賣出兩個分支」變成一條**帶正負號的差額**：

```rust
// ① 目標名目金額 = 目標比例 × 成交前權益（正做多、負做空、>1 是槓桿）
let budget = target.ratio().checked_mul(equity_at_open)?;
// ② 先用沒加滑價的開盤價估一次，只為了知道這一筆是買還是賣
let provisional = budget.checked_div(bar.open)?;
let buying = provisional > qty;
// ③ 目標數量：分母是「成交價 × (1 + 費率)」，和 2.4 完全一樣
let (fill, rate) = costs.quote(bar.open, buying)?;
let want = budget.checked_div(fill.checked_mul(Fixed::ONE.checked_add(rate)?)?)?;
// ④ 這一筆要成交的量 = 目標 − 現況。正數買、負數賣，開空/平空/翻多空都走這一條
let delta = want.checked_sub(qty)?;
cash = settle(cash, delta, bar.open, &costs)?;
qty = want;
```

每根 K 線的順序變成五步（新增第 ① ② 步）：

```text
① 資金費（跨過幾個 8 小時結算點就收付幾次）
② 強制平倉檢查（用開盤價）
③ 成交上一根留下的目標（用開盤價）
④ 用收盤價評價 → 再檢查一次強制平倉 → 記一點權益
⑤ 才問策略這根收盤想要什麼部位
```

錯誤型別多了四個變體：

| 變體 | 什麼時候出現 |
|---|---|
| `InvalidFundingRate` | 資金費率絕對值 ≥ 1（例如把 0.75% 寫成 75）|
| `InvalidMaintenanceMargin` | 維持保證金率 < 0 或 ≥ 1 |
| `NonMonotonicTime` | K 線時間沒有遞增——資金費按時間戳算，時間倒退會反過來收錢 |
| `NegativeEquity` | 算出負的權益。只有關掉強制平倉時才可能發生 |

`EquityPoint`、`run_backtest` 的簽名、`Strategy`／`TargetPosition` 都沒動。

## 為什麼這樣設計

### 方向看的是「這一筆是買還是賣」，不是「目標是多還是空」

這是這一步最容易寫錯的地方，2.4 的交接筆記也特別點了出來：

| 動作 | 送出去的單 | 滑價方向 | 費率邊 |
|---|---|---|---|
| 開多、加多 | 買 | 買貴 | 買方 |
| 減多、平多 | 賣 | 賣賤 | 賣方 |
| **開空、加空** | **賣** | **賣賤** | **賣方** |
| **平空、減空** | **買** | **買貴** | **買方** |

程式裡的判斷條件是 `delta`（目標數量 − 目前數量）的正負，不是 `ratio` 的正負。
把它寫成「做空就用賣價」的話，平空會變成「用賣價買回來」——滑價站到對你有利的
那一邊，一趟來回憑空多賺兩倍滑價。測試 `closing_a_short_pays_the_buy_side_slippage`
就是為了釘死這件事：價格從頭到尾 100，方向寫對是虧 10，寫反是賺 10。

### 為什麼一條 `delta` 就夠，不用分「開倉 / 平倉 / 加倉 / 反手」

2.4 的 `if want_long && qty.is_zero()` 這種寫法，在允許做空與槓桿之後會爆成八個分支
（開多/加多/減多/平多/開空/加空/減空/平空），而且每個分支都要各自算一次手續費。
改成「算出目標數量，成交差額」之後，這八種情況是同一行程式：

- 從 +100 變 0：`delta = −100`，賣 100。
- 從 +100 變 −100：`delta = −200`，一筆賣 200（真實世界也是一張單反手），
  手續費照 200 顆的名目金額收。測試 `flipping_from_long_to_short_is_one_trade`。
- 從 0 變 −100：`delta = −100`，賣 100（開空）。

分支愈少，錯的地方就愈少。這是整個 2.5 唯一真正「重寫」的部分。

### 槓桿倍數的定義：成交前權益 × 倍數，而且這筆預算含手續費

`目標數量 = 目標比例 × 成交前權益 ÷ (成交價 × (1 + 費率))`

分母裡那個 `(1 + 費率)` 是刻意的，它有兩個好處：

1. **槓桿 1 倍、只做多時，這條式子字面上就是 2.4 的
   `現金 ÷ (成交價 × (1 + 費率))`**（因為空手時「成交前權益」就等於現金）。
   四則運算的順序也一樣，所以 2.4 的每一個數字都能原封不動對回來——
   這就是 2.4 作者要求的那條迴歸測試能成立的原因，不是巧合。
2. 手續費是從同一筆預算裡出的，所以**永遠不會發生「開了倉付不出手續費」**。

代價是：成交後實際的「名目金額 ÷ 權益」會比設定的倍數略高一點點
（因為成本讓權益變小了），差距大約等於一趟成本的量級（萬分之幾）。
真實交易所是「先算名目金額，手續費另外從錢包扣」，所以嚴格說這是一個
**保守方向**的近似：我們開的倉永遠不會超過「成交前權益 × 倍數」。

### 為什麼名目金額每根都要重算（固定槓桿會自動再平衡）

目標是「名目金額」而不是「數量」，所以價格一動，目標數量就跟著動：

- **1 倍做多剛好不用調**：資金全部換成部位之後現金是 0，名目金額永遠等於權益，
  算出來的目標和手上的一模一樣，一顆都不會動（這就是 2.4 的行為）。
- **2 倍做多會調**：價格漲 10%，權益漲 20%、名目金額只漲 10%，槓桿掉到 1.83 倍，
  下一根開盤會再買一點補回 2 倍（測試 `a_levered_long_rebalances_back_to_the_target_leverage`）。

這不是 bug，是固定槓桿產品的每日再平衡：**漲了加碼、跌了減碼**，所以來回震盪會
磨損權益（volatility decay）。想做「進場後就不動」的策略，之後要在策略層自己記
進場時的數量，而不是在這裡改記帳方式。

順帶一個細節：當「要成交的量」比一趟成本還小的時候，估出來的方向會和實際要成交的
方向相反（估算用不含成本的價格、目標用含成本的價格）。這一根就完全不動——
硬送一張反方向的單只是白付手續費，而且那張單的數量還是用錯邊的費率算的。
測試 `a_trade_smaller_than_the_round_trip_cost_is_skipped` 固定住這個行為。

### 資金費：現金流，不是價格

`付出的錢 = (數量 × 價格) × 資金費率`，直接加減現金。

方向只有一條規則，靠數量的正負自己分多空：**費率為正 → 多頭付給空頭**。
數量為正（做多）算出來的付出是正的 → 現金變少；數量為負（做空）算出來的付出是負的
→ 現金變多。費率為負時整個反過來（真實市場在空頭情緒濃厚時常見）。

這個方向是 Binance 永續合約的實際機制：資金費率為正表示合約價高於現貨（多方
需求強），就由多方付錢給空方，把合約價往現貨拉。**這是我採用的方向，也和
`positive_funding_moves_money_from_longs_to_shorts` 這條測試的名字一致**；
如果哪天發現搞反了，改一個減號並把那條測試的期望值對調即可。

三個刻意的簡化（都寫在 `backtest.rs` 的模組說明裡）：

| 簡化 | 為什麼可以接受 | 什麼時候要補 |
|---|---|---|
| 全程一個固定費率 | 歷史資金費率要另外抓一份資料（第 4 步的 API 才有），而參數敏感度用「換幾個費率各跑一次」就看得出來 | 要精算長期持倉成本時 |
| 結算價用那根 K 線的開盤價 | 我們沒有結算當下的標記價格 | 同上 |
| 跨幾個結算點就一次收幾次 | 日線一根跨三個結算點，收三次是對的；只是三次都用同一個價格 | 用日線以上週期又要精算時 |

結算點怎麼判斷：Binance 在 UTC 00:00、08:00、16:00 結算，這三個時刻的毫秒時間戳
剛好都是 8 小時的整數倍，所以「上一根開盤到這一根開盤之間跨過幾次」就是兩個
`時間戳 ÷ 8小時` 相減。1 小時 K 線時 9 根裡只有一根會收到費用
（測試 `funding_is_charged_per_eight_hours_not_per_bar`），日線一根收三次
（測試 `a_daily_bar_pays_three_funding_periods`）。

### 強制平倉：這一步為什麼選擇「做一個簡化模型」而不是「回錯誤」

ROADMAP 2.5 字面上只寫「做空、槓桿、資金費」，沒提強制平倉。但是**只要開放槓桿，
就不能不處理它**：2 倍槓桿碰上 50% 的下跌，權益會歸零；再跌下去，帳面權益會變成
負數。而負權益不只是「數字難看」，它會讓後面的記帳整個壞掉——目標名目金額是
`比例 × 權益`，權益變負之後，一個「做多」的策略會算出負的目標數量，
回測會**自己開始做空**，然後吐出一條完全虛構的權益曲線。沒有任何警告。

兩個選項我都評估過：

- **(b) 不做模型、算到負權益就回錯誤。**優點是誠實、程式最少。缺點是
  「回測失敗」這件事本身不帶資訊：使用者只知道爆掉了，不知道**什麼時候**爆、
  爆之前的權益曲線長什麼樣、在那之前賺了多少。而回測工具的價值就在那條曲線。
  一個 2015–2025 的十年回測，只因為 2020-03-12 那天爆倉就整份跑不出來，沒人能用。
- **(a) 做一個簡化的維持保證金模型。**權益掉到 `名目金額 × 維持保證金率` 以下就
  把倉位整個平掉（付滑價與吃單費），現金若被扣成負數就歸零——保證金虧光就是虧光，
  交易所的保險基金吃掉剩下的，帳戶不會倒欠。曲線因此會畫出「這裡爆倉了」這件事，
  而且**權益在結構上永遠不可能是負的**，後面的記帳也就不會被汙染。

**我選 (a)**，因為它同時解決了「不能給假數字」和「要留下可讀的曲線」兩件事，
而程式只多了大約十行（`margin_call`，而且它重用成交用的 `settle`）。
選項 (b) 也沒有丟掉：把 `maintenance_margin_rate` 設成 `None` 就是純記帳模式，
這時權益一變負就回 `NegativeEquity` 錯誤，絕不會拿著負權益往下跑。
兩種模式都有測試（`a_gap_through_the_liquidation_price_leaves_zero_not_a_negative_equity`
與 `without_a_margin_model_a_negative_equity_is_an_error_not_a_number`）。

**但是這個模型有一個一定要知道的簡化：只在開盤價與收盤價檢查，不看盤中的最高最低價。**
真實世界是標記價格一碰到強平價就立刻被平掉，那可能發生在 K 線中間。所以這個回測對
高槓桿策略是**偏樂觀**的：一根長下影線該爆的倉，這裡可能因為收盤又拉回來而活下來。
維持保證金率也沒有照倉位大小分級（Binance 是分級的，倉位愈大要求愈高），
用一個固定的 0.5%（`DEFAULT_MAINTENANCE_MARGIN_RATE`）。要補的時候，正確做法是
「用 `bar.low`／`bar.high` 檢查、在強平價成交」，而不是在這裡疊補丁；
那一步真正的難處是它需要「強平價」這個新概念（含維持保證金分級表），
所以留給之後有真實需求時再做。**在那之前，高槓桿（超過 3 倍）的回測結果只能當
上限看，不能當預期。**

另外一件要知道的事：回測**不會幫你按停止鍵**。一個「永遠 5 倍做多」的策略被平倉之後，
同一根 K 線的開盤就會拿剩下的錢再開一次 5 倍。這是策略的責任，不是回測的；
真實系統的熔斷與人工復核屬於風控層（之後的第 6 步）。如果殘值是 0，
目標名目金額就是 0，帳戶會維持空手到結束——一條躺在 0 的曲線就是「你爆倉了」。

### 為什麼要擋「時間沒有遞增」

2.4 之前完全不看時間戳，所以順序亂了也只是數字沒意義。這一步的資金費是**按時間戳算的**：
時間倒退會算出負的結算次數，等於反過來收錢——一條憑空生錢的路徑。
既然時間開始參與運算，就在迴圈裡直接擋掉（`NonMonotonicTime`），不靠呼叫端自律。

### 既有測試怎麼處理

- 2.2–2.4 的所有行為測試**數字一個字都沒改**，只有兩處機械調整：
  `BacktestConfig` 的結構實字改用 `..BacktestConfig::frictionless(...)` 補齊新欄位，
  測試用的 `LongThenFlat` 改名為通用的 `HoldThenFlat`（多一個 `ratio` 參數）。
- 唯一被**刪掉**的是 `short_target_is_treated_as_flat_for_now`——它斷言的是
  2.4 的暫時行為（做空訊號當成空手），現在做空是真的做空，那條斷言必須消失。
  取代它的是 `a_short_profits_when_the_price_falls`（同一份資料，答案從 10000 變成 15000）。
- `awkward_prices_still_cost_only_slippage_and_fee` 的註解補了一句：它現在同時固定住
  「1 倍滿倉不會每根都調倉」。

### 手算對照一：做空賺錢（`a_short_profits_when_the_price_falls`）

零成本、起始資金 10000，三根 K 線的開收都是 100、100、50，策略永遠 1 倍做空。

| K 線 | 開盤做的事 | 現金 | 數量 | 收盤權益 |
|---|---|---|---|---|
| 0 (100) | 收盤說做空 → 記著 | 10000 | 0 | 10000 |
| 1 (100) | 賣 100 顆 @100 → 現金 +10000 | 20000 | −100 | 20000 − 10000 = **10000** |
| 2 (50) | 價格腰斬，權益 15000；1 倍空的名目金額要跟著變成 15000 → 再賣 200 顆 @50 | 30000 | −300 | 30000 − 15000 = **15000** |

價格跌一半，1 倍做空賺 50%。2.4 的版本會停在 10000（做空訊號當空手），
所以測試裡有一條 `assert_ne!(curve[2].equity, fx("10000"))`。

### 手算對照二：平空要付買方滑價（`closing_a_short_pays_the_buy_side_slippage`）

滑價 0.05%、零手續費、起始資金 9995（挑這個數字讓數量剛好 100 顆），價格全程 100。

| K 線 | 開盤做的事 | 現金 | 數量 | 收盤權益 |
|---|---|---|---|---|
| 0 | 收盤說做空 | 9995 | 0 | 9995 |
| 1 | 開空＝**賣**：成交價 `100 × 0.9995 = 99.95`，數量 `9995 ÷ 99.95 = 100` | 19990 | −100 | 19990 − 10000 = **9990** |
| 2 | 平空＝**買**：成交價 `100 × 1.0005 = 100.05`，付 10005 | 9985 | 0 | **9985** |

價格一動都沒動，一趟來回被滑價吃掉 10 = 兩次 `10000 × 0.05%`。
方向寫反（平空也用賣價）會變成 `19990 − 9995 = 9995`，**憑空多賺 10**。

### 手算對照三：槓桿放大名目金額，手續費跟著放大（`leverage_multiplies_the_fee_not_the_rate`）

合約吃單 0.05%、無滑價、起始資金 10000、價格全程 100。

| 槓桿 | 目標數量 | 名目金額 | 手續費 | 成交當根權益 | 少掉的錢 |
|---|---|---|---|---|---|
| 1 倍 | `10000 ÷ 100.05 = 99.95002499` | 9995.002499 | **4.99750125** | 9995.00249875 | 4.99750125 |
| 2 倍 | `20000 ÷ 100.05 = 199.90004998` | 19990.004998 | **9.9950025** | 9990.0049975 | 9.9950025 |

`9.9950025 = 2 × 4.99750125` 剛好是兩倍，而費率一個字都沒改——這就是
「槓桿放大的是名目金額」的實測。測試裡直接斷言這個等式。

### 手算對照四：資金費（`positive_funding_moves_money_from_longs_to_shorts`）

8 小時 K 線、價格全程 100、費率 0.01%、零交易成本、起始資金 10000。
第 1 根開盤建倉（名目 10000），第 2 根開盤跨過一個結算點：

| 策略 | 資金費 | 第 2 根權益 |
|---|---|---|
| 1 倍做多 | 付 `10000 × 0.0001 = 1` | **9999** |
| 1 倍做空 | 收 1 | **10001** |

多頭付的剛好等於空頭收的（測試裡也斷言了這個對稱）。費率設成 −0.0001 時反過來，
多頭收錢（`negative_funding_pays_the_longs`）。

### 手算對照五：爆倉不可逆（`a_levered_long_gets_liquidated_and_cannot_recover`）

零成本、起始資金 10000、5 倍做多、維持保證金率 0.5%。

| K 線 | 開 / 收 | 這根做的事 | 現金 | 數量 | 權益 |
|---|---|---|---|---|---|
| 0 | 100 / 100 | 收盤說 5 倍做多 | 10000 | 0 | 10000 |
| 1 | 100 / 80.4 | 開盤買 500 顆（名目 50000）；收盤權益 `−40000 + 40200 = 200` ≤ `40200 × 0.5% = 201` → 整個倉位被平掉 | 200 | 0 | **200** |
| 2 | 100 / 100 | 價格回到 100，但只剩 200 可以再開 5 倍（名目 1000 = 10 顆） | −800 | 10 | **200** |

**價格回到原點，帳戶卻只剩 2%。** 沒有強制平倉模型的話，500 顆會一路抱回 100，
第 2 根的權益會完整復活成 10000——那就是回測最危險的假訊號。
做空版（`a_levered_short_gets_liquidated_and_cannot_recover`）數字完全對稱。

跳空更大時（價格直接到 70，帳面權益會是 `−40000 + 35000 = −5000`），現金歸零、
權益是 **0**，不是 −5000（`a_gap_through_the_liquidation_price_leaves_zero_not_a_negative_equity`）。
同一份資料在 `maintenance_margin_rate: None` 下會回 `NegativeEquity { index: 2 }`。

### 迴歸測試：槓桿 1 倍 + 只做多 + 資金費 0 = 2.4 的數字

`unit_leverage_long_only_reproduces_the_2_4_numbers`，三組斷言全部抄自
`docs/steps/2.4-手續費與滑價.md`：

| 資料 | 設定 | 期望（= 2.4 的答案）|
|---|---|---|
| 開收 `(100,100) (100,200) (150,300)` | 零成本 | `[10000, 20000, 15000]` |
| 開收都 100 的四根 | 現貨 0.1% + 滑價 0.05%，資金 10015.005 | `[10015.005, 10000, 9985.005, 9985.005]` |
| 同上 | 換成 `FeeModel::Futures`（費率填成一樣的 0.1%）| 同上，一個字不差 |

第三組是額外加的：它證明「合約記帳路徑」和「現貨記帳路徑」是同一條程式，
差別只在費率數字。再加上 2.2／2.3／2.4 那十幾條數字未動的行為測試，
「合約能退化回現貨」是一整組測試在守，不是只靠這一條。

### 突變測試：確認新測試真的抓得到錯

刻意把程式改壞九次，看有沒有測試變紅（自動化腳本跑完會還原）。實測結果：

| 故意改壞 | 抓到它的測試（節錄）|
|---|---|
| 1. 買賣方向反過來 | `closing_a_short_pays_the_buy_side_slippage`、`a_round_trip_...`、`slippage_alone_...`、2.4 迴歸 |
| 2. 資金費方向反了（多頭收錢）| 四條資金費測試全紅 |
| 3. 資金費每根 K 線都收一次 | `funding_is_charged_per_eight_hours_not_per_bar`、`a_daily_bar_pays_three_funding_periods` |
| 4. 爆倉後不把負現金歸零 | `a_gap_through_the_liquidation_price_leaves_zero_...` |
| 5. 拿掉「差額比成本還小就不動」的保險 | `a_trade_smaller_than_the_round_trip_cost_is_skipped` |
| 6. 買進不預留手續費 | `fee_alone_...`、`a_round_trip_...`、`leverage_multiplies_the_fee_...`、2.4 迴歸 |
| 7. 做空的名目金額掉了負號 | 六條做空／資金費測試 |
| 8. 完全不做強制平倉檢查 | 三條爆倉測試 |
| 9. 忽略槓桿倍數 | 十二條測試 |

九次全部被抓到。過程中有兩個發現值得記下來，因為它們都是「測試看起來有測、其實沒測」：

- 第 5 條一開始**沒有任何測試抓到**。原因是那個保險只在「要成交的量比一趟成本還小」
  的窄帶裡才會觸發，而當時的測試剛好都不在那個窄帶裡。補了
  `a_trade_smaller_than_the_round_trip_cost_is_skipped`（策略先要 0.999 倍、
  下一根改要 1 倍，目標只差 0.1% 而成本是 0.15%）才守住。
  順便也發現原本寫在程式裡的註解是錯的：`settle` 一律用「實際成交方向」定價，
  所以拿掉保險不會生錢，只會白付一次手續費——註解已經改成正確的說法。
- 第 8 條一開始只有一條測試抓到。原因是**固定槓桿策略自己的再平衡會偽裝成強制平倉**：
  被平倉後拿殘值重開 5 倍，和「不平倉、直接調整到 5 倍」的結果一模一樣。
  把爆倉改成發生在**收盤**、下一根價格再拉回來，兩者才分得開（差距是 200 對 10000）。

## 建議閱讀順序

1. `backtest.rs` 模組說明的「合約：帶正負號的倉位」那張表——四種狀態的
   現金／數量／權益，看懂這張表就看懂了整步。
2. 同一份說明的「資金費」與「強制平倉」兩節，特別是強制平倉那段列的已知簡化。
3. `BacktestConfig` 兩個新欄位的文件註解，還有 `BacktestConfig::frictionless`
   為什麼**不**關掉強制平倉。
4. `Costs::quote` 與 `settle` 這兩個小函式：一個決定「買貴還是賣賤、收哪一邊的費率」，
   一個把帶正負號的差額變成現金流。八種倉位變化都走這兩個函式。
5. `margin_call`：注意它重用 `settle`（強制平倉也是市價單），以及最後
   「負現金歸零」那一行。
6. `run_backtest` 迴圈本體，照著 ①資金費 → ②爆倉檢查 → ③成交 → ④評價 → ⑤問策略
   的順序讀，注意每一步為什麼不能換位置。
7. 測試 `unit_leverage_long_only_reproduces_the_2_4_numbers`，對照
   `docs/steps/2.4-手續費與滑價.md` 的手算表格。
8. 測試 `a_levered_long_gets_liquidated_and_cannot_recover`，那張三根 K 線的表
   是這一步最重要的一課。
9. 回頭看 `docs/steps/2.1-策略介面.md` 講「為什麼部位是帶正負號的比例」那一段——
   它當時就預告了「2.5 之後合約要做空、要槓桿」，所以介面先用帶正負號的 `Fixed`。
   這一步兌現了那句話：`Strategy`／`TargetPosition` 真的一個字都沒改。

## 動手試試看

1. 把 `settle` 裡的 `costs.quote(price, buying)` 改成 `costs.quote(price, !buying)`
   （買賣方向反過來），跑 `cargo test -p at-core backtest`。
   `closing_a_short_pays_the_buy_side_slippage` 會從 9985 變成 9995——
   **價格完全沒動，帳戶卻多了 10。** 這就是「回測比實盤好」最常見的來源。
2. 把資金費的 `cash.checked_sub(payment)` 改成 `checked_add`，跑測試：
   四條資金費測試一起紅，多頭變成收錢。想一下如果沒有這幾條測試，
   一個長期持有多頭的策略會被美化多少（0.01% × 每天 3 次 × 365 ≈ 11%／年）。
3. 把 `maintenance_margin_rate` 設成 `None`，拿 5 倍做多跑一段「100 → 100 → 70」的
   K 線（照抄測試裡的 `oc_bars` 就好），確認它回 `NegativeEquity { index: 2 }`
   而不是一條負權益的曲線。然後改回 `Some(...)`，比較兩者——
   爆倉那一根之後權益躺在 0，價格再漲也回不來。
4. 拿 2.7 的內建策略（例如 `SmaCross`）配 1 倍、2 倍、5 倍各跑一次
   （`TargetPosition::new(fx("5"))`），比較最後的權益。大多數在 1 倍能賺的策略，
   到 5 倍會直接爆倉：**槓桿不是把報酬乘 5，是把「能承受的回撤」除以 5。**
5. 把 `funding_rate` 設成 `0.0075`（Binance 的常見上限、2021 年多頭最狂時真的出現過），
   跑一個長期持多的策略。一天結算三次就是 2.25%，一個月就吃掉大半本金——
   這是「做多永續合約長抱」最容易被回測忽略的成本。
6. 把 K 線週期換成日線（`bars_every(24 * HOUR, ...)`），確認一根收三次資金費。
   想一下為什麼「一根收一次」在日線上會少算三分之二的持倉成本。

## 2.6 怎麼接

2.6 要做績效指標：總報酬、年化、最大回撤、夏普、交易次數。和這一步的關係：

- **前四個指標只需要這一步輸出的 `Vec<EquityPoint>`，不用再碰 `backtest.rs`。**
  總報酬 = 最後一點 ÷ 第一點 − 1；最大回撤 = 掃一遍曲線記「歷史最高」與
  「當前距高點的跌幅」；年化與夏普要用 `open_time` 的時間差算出實際跨了多久
  （所以 `EquityPoint` 一直帶著時間戳），別假設一根就是一天。
- **權益可以是 0，但保證不會是負的**（強制平倉模型的直接結果），所以
  「總報酬 = −100%」是合法的輸入，但不會出現「報酬 −150%」這種算不出對數的數字。
  夏普的報酬序列建議用相鄰兩點的比值，遇到 0 要當成「已出場」而不是除以 0。
- **交易次數是唯一這一步沒有輸出的東西。** 現在 `run_backtest` 只回權益曲線，
  沒有記「哪一根成交了幾筆、名目多少、手續費多少」。2.6 做到交易次數時，
  最小的改法是讓 `run_backtest` 回一個結果 struct（權益曲線 + 成交筆數 +
  累計手續費 + 累計資金費 + 有沒有被強制平倉過），而不是在外面重跑一次策略去猜。
  建議順序：先做只吃曲線的四個指標，最後再為交易次數改回傳型別，一次改完。
- **爆倉過的回測要在報表上標出來。**「年化 30%，但中間爆倉一次」和
  「年化 30% 沒爆倉」是完全不同的兩件事。這是那個結果 struct 值得帶一個
  `liquidations: usize` 的主要理由。
