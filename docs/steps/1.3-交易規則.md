# 1.3 交易規則 `SymbolRules`

## 做了什麼

1. `crates/core/src/fixed.rs` 加上取整功能：
   - `floor_to_step(step)`：往下取整到某個倍數，例如以 0.01 為單位時 `1.239 → 1.23`。
   - `ceil_to_step(step)`：往上取整。
   - `is_multiple_of(step)`：是不是剛好是某個單位的倍數。
2. 新增 `crates/core/src/rules.rs`：`SymbolRules`，對應 Binance 對每個交易對的限制。

| 欄位 | Binance 的名稱 | 意思 |
|---|---|---|
| `tick_size` | `PRICE_FILTER.tickSize` | 價格必須是它的倍數 |
| `step_size` | `LOT_SIZE.stepSize` | 數量必須是它的倍數 |
| `min_qty`、`max_qty` | `LOT_SIZE` | 數量上下限 |
| `min_notional` | `NOTIONAL` | 價格 × 數量至少要多少 |

## 為什麼要這樣做

交易所會直接拒絕不合規的單。例如 BTCUSDT 的價格要是 0.01 的倍數，
下 `63880.123` 就會被拒。回測和模擬也要套同一套規則，
否則回測裡會出現「真實世界下不了的單」，績效就會失真。

## 幾個設計決定

- **數量一律往下取整**：往上取整可能超過你想投入的金額或帳戶餘額。
- **限價單價格：買的往下、賣的往上**：取整後的價格只會一樣或對自己更有利，買得更便宜、賣得更貴，不會因為取整多付錢。
- **`check()` 回傳第一個不合規的地方，並附上實際數值**：例如「金額 4.4716084 小於最小金額 5」，出錯時一眼就知道差多少。
- **`qty_for_quote()`**：給一個金額（例如 1000 USDT）算最多能買多少，除法用 `i128` 避免溢位並無條件捨去。

## 怎麼驗證

```bash
cargo test -p at-core rules
cargo test -p at-core fixed
```

應該分別看到 10 個和 13 個測試通過。全部測試 `cargo test` 共 42 個。

## 建議閱讀順序

1. `rules.rs` 最上面的表格
2. 測試 `buy_price_rounds_down_sell_price_rounds_up`、`qty_for_quote_never_exceeds_budget`
3. `SymbolRules::check`：檢查的順序
4. `fixed.rs` 的 `floor_to_step`：為什麼負數要用 `div_euclid`

## 動手試試看

1. 把測試裡 `btc()` 的最低下單金額從 `"5"` 改成 `"10"`，跑 `cargo test -p at-core rules`，看哪些測試會失敗、為什麼。
2. 把 `round_price` 裡買單改成 `ceil_to_step`，跑測試看哪一個測試會抓到。
