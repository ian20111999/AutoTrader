# 1.1 定點數 `Fixed`

## 做了什麼

新增 `crates/core/src/fixed.rs`：一個用整數表示價格、數量、金額的型別 `Fixed`。

## 為什麼要這樣做

電腦的一般小數（`f64`）是二進位的，無法精確表示 0.1：

```
0.1 + 0.2 = 0.30000000000000004
```

交易時這會造成真實問題：Binance 規定 BTCUSDT 的價格要是 0.01 的倍數、數量要是 0.00001 的倍數，
差一點點就會被拒單；累積上萬筆成交後，損益也會對不起來。

解法是把所有數字乘上 1 億（10^8）存成整數：

| 數字 | 內部存的整數 |
|---|---|
| 63880.10 | 6,388,010,000,000 |
| 0.001 | 100,000 |
| -0.5 | -50,000,000 |

整數加減永遠精確。選 8 位小數是因為 Binance 的價格與數量最多就是 8 位。

## 幾個設計決定

- **小數超過 8 位直接報錯**，不默默捨去：寧可讓錯誤浮上來，也不要算錯。
- **相乘時中間用 `i128`**：兩個放大 1 億倍的數相乘會放大 10^16 倍，`i64` 會溢位，所以先用更大的整數算完再除回來。
- **所有運算都叫 `checked_*`**：溢位時回傳 `None`，不會變成一個錯誤的數字繼續往下跑。
- **`to_f64()` 只給統計和畫圖用**：夏普值、報酬率曲線這類不需要精確到最後一位的地方才用。

## 怎麼驗證

在專案資料夾執行：

```powershell
cargo test -p at-core fixed
```

應該看到 9 個 `fixed::tests::...` 全部 `ok`。

## 建議閱讀順序

1. `fixed.rs` 最上面的說明
2. 最下面的測試（`mod tests`）：每個測試名稱就是一條規則，例如 `f64_is_not_exact_but_fixed_is`
3. `from_str`：字串怎麼轉成整數
4. `checked_mul`：相乘與四捨五入

## 動手試試看

1. 在 `rejects_bad_strings` 測試裡加一行 `assert_eq!("1.2.3".parse::<Fixed>(), ...)`，猜猜會回傳什麼錯誤，再跑測試驗證。
2. 把 `multiply_price_by_quantity` 裡的期望值改錯一位數，跑測試看失敗訊息長什麼樣，再改回來。
