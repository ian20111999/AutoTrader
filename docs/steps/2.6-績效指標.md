# 2.6 績效指標：總報酬、年化、最大回撤、夏普、交易次數

## 做了什麼

新增 `crates/core/src/metrics.rs`，把一條權益曲線變成四個數字：

```text
總報酬   = 最後權益 ÷ 第一點權益 − 1
年化報酬 = (最後權益 ÷ 第一點權益)^(1 ÷ 年數) − 1        // CAGR，幾何平均
最大回撤 = 整條曲線裡「離歷史最高點跌最深」的那一次
夏普比率 = (每期報酬平均 ÷ 每期報酬標準差) × √(一年有幾期)
```

用法就一行：

```rust
let result = run_backtest(&bars, &mut strategy, &config)?;
let m = Metrics::from_curve(&result.curve);
```

第五個指標**交易次數不在曲線裡**，所以 `run_backtest` 的回傳型別從
`Vec<EquityPoint>` 改成 `BacktestResult`：

```rust
pub struct BacktestResult {
    pub curve: Vec<EquityPoint>,   // 原本就有的權益曲線
    pub trades: usize,             // 新增：實際送出去的成交筆數
    pub liquidations: usize,       // 新增：被強制平倉幾次
}
```

`EquityPoint` 與 `BacktestError` 一個字都沒改，只是外面多包一層。
`Strategy`、策略實作、`fees`、`downloader` 也都沒動。

另外把整數開根號 `isqrt` 從 `strategies/mod.rs` 搬到 `fixed.rs`
（`pub(crate)`）：夏普的標準差與年化的小數次方都要用它，搬過去兩邊共用，
不是各寫一份。策略的行為完全沒變（`Window::stddev` 的算式一個字沒改）。

## 為什麼這樣設計

### 指標只吃曲線，不吃策略

`metrics.rs` 只看得到 `&[EquityPoint]`，不知道策略、手續費、槓桿長什麼樣子。
好處是測試可以直接手寫一條 5 個點的曲線去驗，不必先跑一次回測；
壞處是它算不出交易次數——那正是下面要改回傳型別的原因。

### 交易次數：改回傳型別，不在外面重跑策略猜

交易次數看曲線是猜不出來的：權益不動可能是沒交易，也可能是「在平盤來回買賣、
成本剛好被四捨五入吃掉」。唯一知道這件事的是回測迴圈本身。

兩個選擇：

1. 在外面重跑一次策略，自己數它想要幾次調倉。**錯的**——策略想要的和實際送出去的
   不一樣（`a_trade_smaller_than_the_round_trip_cost_is_skipped` 那種「成本比價差大就
   放棄調倉」的情況，還有強制平倉這種策略根本沒要求的成交）。
2. 讓迴圈自己數，回傳出來。

選 2。多帶 `liquidations` 的理由是**它也是曲線裡看不出來的**：2.5 就發現
「固定槓桿策略自己的再平衡會偽裝成強制平倉」，兩者的權益序列可以幾乎一樣。
報表上「年化 30%、中途爆倉一次」和「年化 30%、全程沒爆倉」是完全不同的兩件事，
所以這個數字要單獨記。

沒有順便加「累計手續費／累計資金費」：這一步沒有任何指標需要它們。
要加的時候是在 struct 上多一個欄位，比現在多寫一份用不到的累加器便宜。

**強制平倉算一筆 `trades`**，因為它真的是一張市價單、真的付了滑價與吃單費。
想知道「其中幾筆不是策略決定的」就看 `liquidations`。

### 年化：用時間戳算年數，不用根數

```text
年數 = (最後一點的 open_time − 第一點的 open_time) ÷ 一年的毫秒數
```

一年固定當 **365 天**（`MS_PER_YEAR`，幣圈全年無休，沒有「交易日」的概念）。

絕不假設「一根 K 線 = 一天」。同一份程式要同時吃 1 分線與日線，
把根數當天數會讓 1 分線的年化差上 1440 倍。這也是 2.5 讓 `EquityPoint`
一直帶著 `open_time` 的原因，這一步才兌現。

年化用的是**幾何平均（CAGR）**，不是「總報酬 ÷ 年數」。最短的反例：
兩年翻倍的年化是 √2 − 1 = **41.42%**，不是 50%——算成線性會高估 8.6 個百分點，
而且時間越長差越多。測試 `annualized_return_is_geometric_not_linear` 就是釘這件事。

### 小數次方怎麼在定點數裡算（不碰 `f64`）

`^(1 ÷ 年數)` 的指數幾乎永遠是小數，但專案規定不准用 `f64`
（理由和 2.7 一樣：同一份輸入必須永遠得到同一個數字）。做法是把指數拆兩半：

- **整數部分**用平方累乘：`x^13 = x^8 × x^4 × x^1`。
- **小數部分**展開成二進位，每一位對應一次開根號：
  `x^0.5 = √x`、`x^0.25 = √√x`、`x^0.75 = √x × √√x`。

於是整條路徑只用到「整數開根號 + 定點數乘法」，不需要 `exp`／`ln`，
也不必引入任何新套件。小數部分用 32 位二進位展開（`(小數 << 32) ÷ 10^8`），
**不是**把 `10^8` 一直除以 2——後者每除一次就截尾一次，越除越偏。

代價寫清楚：最多 32 次開根號、每次四捨五入一次，累積誤差量級約 **10^-7**。
`1.5^0.3` 真值是 1.129346968…，這裡算出 1.12934689，差 8×10^-8。
報表顯示到小數第 4 位（0.01%）完全沒問題，但不要拿最後兩位小數去對別人的答案。

### 夏普比率的三個假設（看報表的人一定要知道）

1. **取樣頻率 = K 線週期。**報酬序列是相鄰兩點的比值，1 小時 K 線就是每小時一個樣本。
   沒有重新取樣成日頻或月頻——重新取樣要先決定「跨週末怎麼補點」之類的規則，
   規格還不清楚就不做。
2. **一年的期數是算出來的，不是寫死的常數。**`每年期數 = 報酬個數 ÷ 年數`，
   所以 1 小時 K 線自動得到約 8760、日線自動得到約 365。
   **寫死 365 去年化 1 小時的報酬，夏普會少算約 4.9 倍**（√8760 ÷ √365 ≈ 4.9），
   這是這個指標最常見的錯，測試 `sharpe_annualizes_with_the_actual_sampling_frequency`
   專門釘它。
3. **無風險利率 = 0。**幣圈回測的慣例。沒有做成參數，是因為加了就得先決定它的
   計息頻率（年利率？每期利率？複利？），規格不清楚之前不無中生有。
   要算非 0 的版本，就在報酬序列上先減掉每期的無風險報酬，再套同一條式子。

標準差用**母體**（除以 n），和 `strategies` 裡 `Window::stddev` 同一個慣例。
pandas 的 `.std()` 預設是**樣本**（除以 n−1），這件事在 2.8 會咬人，下面再講。

### 最大回撤：從歷史最高點算，不是從起點算

```text
回撤(t) = (到 t 為止的歷史最高權益 − 當下權益) ÷ 到 t 為止的歷史最高權益
最大回撤 = 整條曲線裡最大的那個回撤
```

兩個邊界要分清楚：

- **一路創新高**（每一點都是新高）→ 回撤 0。
- **創新高後又跌** → 從那個高點算跌幅，不是從起點算。
  `10000 → 20000 → 15000 → 30000` 的最大回撤是 **25%**，
  雖然權益從頭到尾沒有低於起始的 10000。只看「有沒有虧錢」會整段漏掉。

### 權益是 0：合法輸入，不是錯誤

2.5 的強制平倉模型保證權益**永遠不會是負的，但可以剛好是 0**。所以：

- 總報酬 −100%、最大回撤 100% 是正常結果。
- 年化 = `0^(1÷年數) − 1` = −100%，不會除以 0。
- 報酬序列遇到「前一點是 0」時記 **0**，不是除以 0：帳戶歸零之後現金與倉位都是 0
  （見 `backtest::margin_call`），權益不可能再動。這不是近似，是事實。

### 算不出來就回 `None`，不掛一個 0 上去

`Metrics` 除了 `max_drawdown` 都是 `Option<Fixed>`。回 `None` 的情況：
空曲線、只有一點的曲線、第一點權益是 0、標準差是 0（完全沒波動，夏普是 0÷0）、
或中間某一步溢位。報表上寫「無法計算」是誠實的；掛一個 0 會被當成「夏普 0」而誤導。

`max_drawdown` 不是 `Option`，因為它永遠算得出來——沒有曲線就是 0。

### 手算對照：一條 5 個點的權益曲線

測試 `the_hand_computed_curve_matches_all_four_metrics`。每個點間隔剛好一年
（挑這個間隔是為了讓「每年 1 期」、`√(每年期數) = 1`，年化倍數不會插進手算裡）：

| 期 | 權益 | 報酬 |
|---|---|---|
| 0 | 10000 | — |
| 1 | 12000 | +20% |
| 2 | 14400 | +20% |
| 3 | 12960 | −10% |
| 4 | 11664 | −10% |

四個指標一個一個手算：

| 指標 | 手算 | 答案 |
|---|---|---|
| 總報酬 | 11664 ÷ 10000 − 1 | **0.1664** |
| 最大回撤 | 歷史最高 14400、最低 11664 → 2736 ÷ 14400 | **0.19** |
| 夏普 | 平均 = (0.2 + 0.2 − 0.1 − 0.1) ÷ 4 = 0.05；離差都是 ±0.15 → 母體變異數 0.0225 → 標準差 **剛好 0.15**；每年 1 期 → √1 = 1；0.05 ÷ 0.15 | **0.33333333** |
| 年化 | 4 年、總成長 1.1664 = 1.08² → 1.1664^(1÷4) = √1.08 | **0.03923048** |

（年化驗算：1.03923048² = 1.0799999990…，四捨五入回 1.08；
測試 `annualized_return_compounds_back_to_the_total_return` 再把它四次方推回 1.1664。）

這組數字是刻意挑的：**標準差剛好是 0.15 這個整數**，所以夏普手算得完，
不用跟一個開不盡的根號糾纏。

### 接得起來嗎：`metrics_read_a_real_backtest_curve`

真的跑一次回測再算指標。4 根 K 線、每根間隔剛好三分之一年，
所以整段回測**剛好跨 1 年**——這時候年化報酬必須等於總報酬（一年的複利就是它自己）。
對不上就是年數或 `pow` 算錯了。順便驗 `trades == 1`：1 倍滿倉做多只需要一筆單。

## 建議閱讀順序

1. `metrics.rs` 模組說明最上面那四條公式——先知道要算什麼。
2. 同一份說明的「夏普比率的三個假設」。**這三條是報表能不能被信任的前提**，
   尤其第 2 條（年化常數不能寫死）。
3. 測試 `the_hand_computed_curve_matches_all_four_metrics` 上面那張手算表，
   自己拿計算機按一次。
4. `max_drawdown` 函式本體，只有 20 行，注意 `peak` 是怎麼更新的，
   再對照 `drawdown_is_measured_from_the_peak_not_from_the_start` 的曲線。
5. `sharpe` 函式，特別是最後兩行的「每年期數從時間戳算」。
6. `pow` 的說明與本體——小數次方怎麼用連續開根號展開。看不懂也不影響用，
   但看懂了就知道為什麼最後兩位小數不能盡信。
7. `backtest.rs` 的 `BacktestResult` 文件註解，還有迴圈裡三個 `trades += 1`
   出現的位置（成交一次、開盤爆倉一次、收盤爆倉一次）。
8. 回頭看 `docs/steps/2.5-合約.md` 最後的「2.6 怎麼接」，
   對照這一步實際做的取捨——大方向照做，但沒有順便加累計手續費／資金費。

4. 拿同一個策略配 5 倍槓桿跑一次，看 `liquidations` 是不是 > 0。

   報表上必須先講爆倉，再講報酬。
5. 手動組一條「先賺 100% 再虧 50%」的曲線（10000 → 20000 → 10000），
   算它的總報酬（0）與最大回撤（50%）。
   再組一條「先虧 50% 再賺 100%」（10000 → 5000 → 10000），
   總報酬一樣是 0，但最大回撤也是 50%。
   **兩條曲線的指標幾乎一樣，實際體驗天差地別**——想一下報表上還該加什麼
   （提示：回撤持續多久、什麼時候發生）。
6. 把回測資料砍到只剩 3 根 1 分線，看 `annualized_return`。
   它要嘛是天文數字、要嘛是 `None`。這不是 bug，是「年化短區間本身沒有意義」。
   看年化之前先看 `span_years`。

## 2.8 怎麼接

2.8 是「和之前的 Python 回測結果比對」。這一步輸出的五個數字就是比對的欄位，
但**專案裡目前沒有 `docs/reference/`，也沒有任何 Python 標準答案檔**，
所以 2.8 的第一件事不是寫程式，是把那份標準答案拿進來。建議：

1. **先固定輸入再比指標。**同一份 K 線 CSV、同一組參數、同一個費率與滑價設定，
   兩邊各跑一次，把 Python 的權益曲線也存成 CSV。指標對不上有兩種可能
   （曲線就不一樣／曲線一樣但指標公式不同），先比曲線才分得開。
2. **指標對不上時，比對的順序固定成這樣**：`span_years` → 總報酬 → 最大回撤 →
   年化 → 夏普。前面對了後面才有意義；`span_years` 放第一個，
   是因為年化與夏普都拿它當分母，它錯了後面兩個一定跟著錯。
3. **已知會差的三個地方，先去看它們，不要瞎找**：
   - **標準差的自由度**：這裡用母體（÷ n），pandas 的 `.std()` 預設是樣本（÷ n−1），
     差一個 `√(n ÷ (n−1))` 的倍數。n 大幾乎看不出來，n 小很明顯。
   - **一年的定義**：這裡是 365 天，Python 可能寫 365.25 或 252（股票的交易日慣例，
     幣圈不該用）。
   - **年化的取樣頻率**：這裡從時間戳算，很多 Python 腳本是寫死的常數。
   - 第 8 位小數以下的零星差異是 `pow` 的 10^-7 誤差，不用追。
4. **`trades` 與 `liquidations` 也要比。**指標全對但交易次數差很多，
   代表兩邊的成交規則不一樣（最可能是「放棄微小調倉」那條規則，Python 通常沒有），
   這種情況下指標對上只是巧合。
