# 2.3 成交模擬：訊號在收盤、下一根開盤成交

## 做了什麼

只改 `crates/core/src/backtest.rs`，把 2.2 刻意留下的偷看未來修掉。對外介面
（`run_backtest` 的簽名、`EquityPoint`、`BacktestError` 的三個變體）完全沒動。

迴圈裡多了一個變數，每根 K 線的順序從三步變成明確的三段：

```rust
let mut pending: Option<TargetPosition> = None;   // 上一根收盤算出、還沒成交的目標

for (index, bar) in bars.iter().enumerate() {
    if let Some(target) = pending.take() {
        // ① 成交：用「這根的開盤價」bar.open 換手
    }
    // ② 評價：用「這根的收盤價」bar.close 算 EquityPoint
    pending = Some(strategy.on_bar(bar));   // ③ 才問策略，答案留到下一根
}
```

對照 2.2：成交價從 `bar.close`（同一根）換成 `bar.open`（下一根），並且
`strategy.on_bar` 從「評價之前」移到「評價之後」。四個邊界行為因此固定下來：

| 情況 | 行為 |
|---|---|
| 第一根 | `pending` 是 `None` → 只觀察、只評價，不換手（起始是空手） |
| 最後一根 | 算出的目標沒有下一根可成交 → 直接作廢，不影響已記完的曲線 |
| 開盤價 ≤ 0 | 只有**真的要成交**那根才檢查 → `NonPositivePrice { index }` |
| 空的 `bars` | 和 2.2 一樣，不是錯誤，回傳空曲線 |

`NonPositivePrice` 的說明與錯誤訊息從「收盤價」改成「價格」——現在它同時管
成交用的開盤價和評價用的收盤價。變體名稱與欄位沒變，呼叫端不用改。

## 為什麼這樣設計

### 為什麼「下一根開盤」比「本根收盤」更接近真實

收盤價要等收盤才知道。策略看到第 N 根的收盤價才決定要買，這個決定最快也只能
送到第 N+1 根的開盤才成交——中間隔著一次跳空。2.2 用第 N 根的收盤價成交，等於
「看完價格才決定、卻還拿得到那個價格」，這是回測最典型的偷看未來
（look-ahead bias），也是實盤績效普遍比回測差的頭號原因。

差距有多大？測試 `entry_fills_at_the_next_open_not_at_this_close` 是實測：

| K 線 | 開盤 | 收盤 | 舊模型（本根收盤成交） | 新模型（下一根開盤成交） |
|---|---|---|---|---|
| 0 | 100 | 125 | 用 125 買 → 80 顆，權益 10000 | 只觀察，權益 10000 |
| 1 | 100 | 200 | 80 × 200 = **16000** | 用 100 買 → 100 顆，100 × 200 = **20000** |

同一份資料、同一個策略，兩個模型差 4000（40%）。這次新模型還比較好，因為
開盤跳低讓它買得更便宜——**重點不是誰的數字漂亮，是舊模型的數字根本拿不到**。
反過來的例子在 `exit_fills_at_the_next_open_so_the_gap_counts`：決定出場時看到的是
200，真正成交在下一根開盤 150，帳上少 5000。跳空對自己有利或不利都不保證，
這正是回測必須算進去的風險。

### 為什麼需要 `pending`，而不是「往後看一根」

另一種寫法是迴圈裡直接看 `bars[index + 1].open`。沒有採用，理由是：

- 那等於讓迴圈自己去翻未來的 K 線。現在的寫法只允許用「手上這根」的資料，
  結構上就防止了偷看未來——想作弊得先改結構，不是改一個索引。
- 5、6 的模擬交易與實盤是即時餵一根進來，下一根還不存在。`pending`
  這種「先記著、等下一根開盤再執行」的寫法照抄就能用，往後看的寫法不能。

### 為什麼先成交、再評價、最後才問策略

順序錯了就會有一根 K 線的落差：

- 若「先評價再成交」→ 換手當根的權益還是用舊部位算的，等於成交晚了一根。
- 若「先問策略再評價」→ 策略這根的決定會影響這根的評價，2.2 的偷看未來就回來了。

所以成交在最前（用開盤價，資訊到開盤為止）、評價在中間（收盤價，這根結束的真實總值）、
問策略在最後（它看得到整根，但答案只能用在下一根）。

### 開盤價只在要成交時才檢查

價格檢查放在 `if let Some(target)` 裡面，代表沒有換手的 K 線不會因為開盤價
是 0 而讓整個回測失敗——因為那個價格根本沒被拿去算錢。第一根的開盤價永遠用不到，
測試 `non_positive_price_is_rejected` 最後一段就把這個界線釘住：只有真的被當成
成交價的數字才要求是正數。

### 測試資料必須 `open != close`

2.2 的 `bars()` 造出 `open == high == low == close` 的 K 線，兩種成交模型在它身上
算出來一模一樣——這就是為什麼 2.2 的測試全綠也擋不住偷看未來。所以這一步先加了
`oc_bars(&[(開盤, 收盤), ...])`，跟成交時點有關的三個測試都用它：

- `entry_fills_at_the_next_open_not_at_this_close`：進場價是下一根開盤
  （並且 `assert_ne!` 明確排除舊模型的 16000）。
- `exit_fills_at_the_next_open_so_the_gap_counts`：出場價是下一根開盤，跳空照算。
- `a_single_bar_never_trades`：只有一根時目標作廢，價格從 100 衝到 500 也賺不到。

`bars()` 留著給不在乎成交時點的測試用（空手、零頭、溢位、錯誤處理）。

### 既有測試怎麼處理

| 測試 | 這一步做了什麼 | 為什麼 |
|---|---|---|
| `empty_bars_give_an_empty_curve`、`non_positive_capital_is_rejected`、`flat_strategy_keeps_equity_flat`、`short_target_is_treated_as_flat_for_now` | 完全沒動，仍然通過 | 和成交時點無關 |
| `all_in_long_compounds_price_moves`、`selling_locks_in_the_gain`、`rounding_leftover_stays_in_cash`、`works_through_a_boxed_strategy` | 前面加一根「觀察根」，斷言的數字不變 | 進出場都晚一根，補一根就對得回原本的手算 |
| `the_exit_bar_own_move_still_counts` | 刪掉 | 它釘的是「決定那根自己的跌幅照算」，那是舊模型的行為，已被 `exit_fills_at_the_next_open_so_the_gap_counts` 取代 |
| `non_positive_price_is_rejected` | 從 1 個情況變 3 個 | 現在有兩種價格（成交／評價），外加「第一根開盤價用不到」 |
| `extreme_numbers_return_an_error_instead_of_panicking` | 資料從 1 根變 2 根，錯誤從 `index: 0` 變 `index: 1` | 溢位發生在除法，而除法現在發生在下一根開盤 |

## 怎麼驗證

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
```

`at-core` 143 個測試通過（其中 13 個是 `backtest::tests::*`）、`at-downloader` 10 個通過
（1 個需要網路、預設 ignore）、doc-test 1 個通過。

```bash
cargo test -p at-core backtest
```

手算對照（測試 `exit_fills_at_the_next_open_so_the_gap_counts`，起始 10000）：

| K 線 | 開盤 | 收盤 | 這根做的事 | 權益 |
|---|---|---|---|---|
| 0 | 100 | 100 | 收盤說做多 → 只記著 | 10000 |
| 1 | 100 | 200 | 開盤 100 買 100 顆；收盤說空手 → 記著 | 100 × 200 = 20000 |
| 2 | 150 | 300 | 開盤 150 全部賣掉 → 現金 15000；之後漲到 300 與我無關 | 15000 |

要看的是最後一列：**賣在 150，不是賣在第 1 根收盤看到的 200**，也不是第 2 根的
收盤 300。決定與成交隔著一次跳空，這 5000 就是「訊號價不等於成交價」的代價。

## 建議閱讀順序

1. `backtest.rs` 最上面的模組說明——「每根 K 線的順序固定是三步」那一段。
2. `run_backtest` 的迴圈本體，照著 ①成交 → ②評價 → ③問策略 的順序看，
   特別注意 `pending.take()`：取出來就清空，所以同一個目標不會成交兩次。
3. 測試 `entry_fills_at_the_next_open_not_at_this_close`，連同裡面的
   `assert_ne!(curve[1].equity, fx("16000"))`——那行就是「舊模型會答什麼」。
4. 測試 `exit_fills_at_the_next_open_so_the_gap_counts`，感受跳空的方向不由你決定。
5. 測試 `a_single_bar_never_trades`：最後一根的目標作廢長什麼樣。
6. 回頭看 `docs/steps/2.2-最簡回測迴圈.md` 的「2.3 要改什麼」，對照預估與實作。

## 動手試試看

1. 把 `if let Some(target) = pending.take()` 裡的 `let fill = bar.open;` 改成
   `bar.close`（只改成交價，其他不動），跑 `cargo test -p at-core backtest`。
   3 個測試會壞，實測到的數字是：
   - `entry_fills_at_the_next_open_not_at_this_close`：`[10000, 10000]`，應該是 `[10000, 20000]`
     ——改成這樣是「下一根**收盤**才成交」，第 1 根用 200 買進，當根還來不及有損益。
   - `exit_fills_at_the_next_open_so_the_gap_counts`：`[10000, 10000, 15000]`，應該是 `[10000, 20000, 15000]`。
   - `non_positive_price_is_rejected`：開盤價不再被拿去成交，所以把它設成 0 也不再是錯誤。

   換句話說「延一根」和「用開盤價」是兩件獨立的事，兩件都要對。
2. 把 `pending = Some(strategy.on_bar(bar));` 搬到 `curve.push(...)` 之前，跑測試：
   全部照過——因為 `on_bar` 不影響這根的評價，順序在這裡不重要。
   再把同一行搬到成交那段（`if let Some(target) = ...`）**之前**，這次 5 個測試會壞，
   例如 `a_single_bar_never_trades` 變成 50000（開盤 100 買進、收盤 500 評價）、
   `entry_fills_at_the_next_open_not_at_this_close` 第一點變成 12500。
   那等於「看完整根收盤，再回頭用這根的開盤價成交」——比 2.2 更誇張的偷看未來。
   關鍵的順序只有一個：**成交必須在問策略之前**。
3. 拿 `oc_bars` 自己造一組跳空對自己不利的資料（例如做多後下一根開盤直接跌 20%），
   先手算權益再跑 `run_backtest`，確認回測不會幫你美化。
4. 在最後一根讓策略喊做多（例如 `LongThenFlat` 改成只有最後一根做多），
   確認權益完全沒變——目標作廢不是 bug，是「還沒來得及執行」。
5. 把 `bad_open[1].open` 的 0 改成負數，確認錯誤還是 `NonPositivePrice { index: 1 }`，
   而不是算出一個負數量的部位。
