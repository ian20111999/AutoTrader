# 桌面 App 畫面設計稿參考

這份文件整理自使用者提供的 claude.ai Design canvas（`自動交易系統介面設計` v0.3，
連結：`https://claude.ai/artifact/NUreRyfxXWXz8m53onzHG3`），對應專案 `CLAUDE.md`
裡提到的「畫面設計稿」。內容是 **ROADMAP 第 3 步（Tauri + React 桌面 App）** 的
UI/UX 參考，現在（1.x / 2.x，純 Rust 引擎）還不需要看，等做到第 3 步或之後要
排版面、命名 API 回傳欄位時再回來查。

設計稿共 13 個畫面（`project/*.dc.html`），深色主題（背景 `#0B0E13`），字型
IBM Plex Sans + Noto Sans TC（中文）+ JetBrains Mono（數字）。整體設計稿附註
（v0.3 說明）強調：**沒有固定的「調參 → 回測 → 上線」線性流程**，策略庫、編輯器、
回測、部署可以隨時互相切換；「模擬交易」用即時行情、模擬成交、不動用資金，
按停止才結束，可同時跑多個；「部署」頁的檢查只是提醒，不會擋住操作，除非在
風控頁開「嚴格模式」。

## 各畫面摘要

### Main（總覽）
帳戶總覽首頁。頂部 4 張卡片：帳戶權益（USDT）、今日損益、執行中策略數（依
實盤/模擬/測試網分類）、合約保證金健康度（強平距離、有效槓桿、今日資金費）。
中段：60 天權益曲線圖 + 連線與額度面板（行情串流/下單通道/帳戶回報延遲、
下次資金費結算倒數、下單頻率與單日虧損上限用量）。下段：執行中策略列表
（策略/市場/交易對/週期/模式/今日損益/部位/狀態）+ 最近回測列表（連到 Compare）。

### TopBar（共用元件）
頂部列：頁面標題、麵包屑、模式徽章（實盤/模擬/測試網/回測/多策略混合，
不同顏色）、Binance 連線延遲、帳戶回報狀態、帳戶權益、今日損益、右側常駐
「全部停止」紅色按鈕（停止所有策略並撤銷所有掛單）。

### SideNav（共用元件）
左側導覽：總覽 / 研究組（策略庫、策略編輯器、回測）/ 交易組（模擬交易、部署、
即時交易、高頻監控）/ 系統組（風控、設定）。底部有「引擎節點」狀態卡片
（本機或東京節點、延遲、運行時間）。

### Strategies（策略庫）
策略卡片列表（我的策略 / 內建範本 tab），每張卡顯示：名稱、標籤（K線級/Tick級/
高頻、市場、槓桿、狀態：實盤中/模擬中/測試網中/未部署）、回測次數與最近時間、
**回測年化 / 回測最大回撤 / 近 30 天實際報酬** 三個數字 + 小型權益走勢 sparkline、
操作按鈕（調參數/回測/模擬/部署）。下方「從範本開始」9 個內建範本卡片：
均線交叉、RSI 均值回歸、布林通道突破、唐奇安通道突破、網格交易、定期定額、
資金費率套利、造市、掛單簿失衡，另有「匯入自訂程式（WASM）」入口。

### StrategyEditor（策略編輯器）
拖拉積木式條件編輯器。頂部：策略名稱/版本/未儲存標記、市場切換（現貨/U本位
合約）、方向（只做多/多空）、槓桿、保證金模式（逐倉/全倉）、週期、交易對數、
「執行回測」按鈕。左側積木庫分類：**指標**（SMA、EMA、RSI、MACD、布林通道、
ATR、唐奇安高低點、成交量）、**合約資料**（資金費率、標記價格、未平倉量、
多空比）、**價格**（開高低收）、**比較運算子**（大於/小於/向上穿越/向下穿越/
持續N根）。中間：做多進場/做多出場條件群組（AND/OR、可巢狀）、做空條件（多空
模式才啟用，預設鏡像多單）、停損與部位設定（交易所端停損、移動停損、每幣部位%
權益、槓桿）。右側：即時預覽K線圖 + 快速回測結果卡（年化/最大回撤/近12個月）。

### Backtest（回測）
左側參數面板：策略選擇、市場（現貨/合約）、方向、週期、保證金模式、槓桿拉桿
（>2x 標示超過風控上限）、交易對多選（10幣）、策略專屬參數（如唐奇安的
「突破前N根進場/跌破前M根出場」拉桿）、手續費來源（帳戶實際費率）、滑價/邊、
「計入真實歷史資金費率」開關、參數掃描/另存版本按鈕。中間：健檢摘要（良好/
注意項目列表）、操作按鈕（儲存回測/加入比較/開始模擬/部署）、**績效指標卡片：
驗證期年化、最大回撤、夏普值、近12個月、手續費+滑價年化成本、資金費年化成本**、
驗證期累積報酬曲線圖（策略 vs BTC持有）、參數穩定度熱力圖（雙參數網格 × 年化）、
逐年表現表格（策略年度報酬 vs BTC持有）、各幣種對總報酬貢獻條狀圖。

### Compare（回測比較）
多筆回測並排比較（可加入/移除）。累積報酬疊圖（含回撤切換）、關鍵發現摘要
（例如「只改槓桿1x→2x：年化+19.8%→+33.7%，但最大回撤-18.3%→-34.1%」）、
**指標比較表**：策略/參數、市場、年化、最大回撤、夏普、逐年報酬（2024/2025/
2026至今/近12個月）、交易次數，並含 BTC買入持有基準列。

### PaperTrading（模擬交易）
可同時管理多個模擬（運行中/已停止標籤 + 起訖與報酬）。當前選中模擬的頂部卡：
策略名、市場、槓桿、虛擬資金、運行時長、費用假設說明、暫停/停止按鈕。指標卡：
模擬權益、同期回測報酬（含差距）、最大回撤、手續費、滑價、資金費。「模擬 vs
回測」對比圖（同一段即時行情）+「回測與模擬的差距」拆解卡（成交時點價差、
滑價差異、資金費差異、手續費差異、其他，逐項列出百分比貢獻）。下方：模擬部位
表（交易對/方向/數量/模擬開倉價/即時標記價/未實現損益/資金費）+ 模擬成交明細
（時間/交易對/方向/成交價/類型 掛單或吃單/手續費/滑價）。

### LiveTrading（即時交易，單一策略聚焦視圖）
K線圖（1h/4h/1d 切換、標記價/最新價切換、成交紀錄/資金費紀錄 tab）、掛單簿、
成交明細、策略日誌四個區塊（因檔案過大只完整讀取結構標題，細節欄位未逐一
列出，但已確認含 **保證金率、強平價、未實現損益、累計資金費** 等合約風控欄位，
與 Risk 頁提到的「合約欄位：槓桿、強平價、距強平、保證金率、累計資金費、
資金費率倒數、交易所端停損」一致）。

### GoLive（部署）
「部署前檢查」清單（6項：驗證期報酬為正、最大回撤在風控上限內、參數穩定度、
模擬交易結果與回測接近、測試網完整跑過下單/停損/撤單/斷線重連、風控上限已
設定），每項標「良好/注意/未開始」，**不會擋住部署**（除非風控頁開了嚴格模式）。
這個版本的模擬交易結果小圖。右側部署設定：部署到測試網/實盤切換、選擇要部署
的回測版本、參數摘要、投入資金、槓桿、單日虧損上限、策略回撤停止%、風險估計
（依回測最大回撤推算可能虧損金額、預估月交易成本）、部署按鈕、嚴格模式開關。

### Risk（風控）
**全域上限**：單筆金額上限、單一幣種部位上限、總部位上限、單日虧損上限
（USDT）、價格偏離保護、下單頻率自我上限（% 交易所限制）、嚵格模式開關。
**合約風控**：槓桿上限（預設2倍，超過拒絕下單）、保證金模式、強平距離下限
（低於拒絕加倉、低於一半自動減倉）、資金費率預算（超過警示並減倉）、交易所端
停損（強制開啟）、套利淨曝險上限。**熔斷規則**：連續虧損5筆→暫停策略、行情
中斷>3秒→暫停高頻並撤單、1分鐘拒絕率>20%→暫停策略、對帳不一致→暫停下單
（強制開啟）、單策略回撤超過上限→停止並撤單。**一鍵停止行為**：預設「停止並
撤銷掛單、保留部位」，另一選項「停止、撤單並市價平倉」；失聯保護（斷線>10秒
交易所自動撤合約掛單）。**觸發紀錄**列表。

### Settings（設定）
交易所帳戶（API Key、金鑰類型 Ed25519、儲存位置=系統鑰匙圈、測試網/正式環境
切換、權限檢查清單含「提幣：已確認關閉」、IP白名單、合約帳戶設定、**帳戶手續費
每24小時自動同步，回測/模擬/實盤共用**）。引擎節點（本機 vs 東京節點，東京
US$73–171/月、未租用、適合高頻策略）。

### HFTMonitor（高頻監控）
微秒級延遲監控：行情→下單 p50/p99/p99.9、下單回應p99、行情訊息速率、頻率
限制用量。延遲分佈直方圖、延遲走勢圖（p50/p99）、熱路徑分段耗時（行情解析/
掛單簿更新/策略決策/風控檢查/編碼送出，各自µs與佔比）。報價狀態（我方買賣價、
價差、庫存偏移）、庫存走勢圖（含上下限虛線）、事件日誌。設計稿標註「需要東京
節點（尚未租用）· 設計示意」——即這頁目前是純示意，尚無實際依據。

## 跟目前正在做的 Rust 引擎步驟的關聯

1. **對應 ROADMAP 2.6（績效指標）**：Backtest / Compare 畫面明確要求
   **年化報酬、最大回撤、夏普值、交易次數**，另外還有「近12個月報酬」、
   「手續費+滑價年化成本」「資金費年化成本」這幾個 2.6 清單裡沒寫但畫面會
   用到的衍生指標（可以在 2.6 的指標結構上加，或留給之後的 App 層自行從
   基礎指標算出，不一定要引擎直接吐）。逐年表現、參數穩定度熱力圖、各幣種
   貢獻，這些是「同一組指標對不同切片（年度/參數/幣種）重算」，不影響 2.6
   本身的資料結構設計，但代表 2.6 的指標計算應該設計成可以對任意子區間/子集
   重複呼叫。

2. **對應 ROADMAP 2.7（內建策略）**：StrategyEditor 積木庫具體點名了指標與
   參數：SMA、EMA、RSI、MACD、布林通道、ATR、唐奇安高低點。目前 2.7 清單是
   「均線交叉、布林通道、唐奇安突破、RSI」，MACD 和 ATR 不在目前清單裡——
   可能是編輯器積木比 2.7 範圍更廣（讓使用者自由組合），不代表 2.7 一定要
   實作 MACD/ATR 策略，但如果之後要做到「自訂策略編輯器」等級的彈性，MACD/
   ATR 計算模組會用到。唐奇安突破的具體參數命名是「突破前N根最高價進場／
   跌破前M根最低價出場」（此案例用 100/10），布林通道範例用「20日 / 1.5
   倍標準差」，均線交叉範例用「10 / 50」，RSI 範例提到「14 / 20 / 50」
   （可能是週期14、超賣20、超買50一類的三參數）。做 2.7 時可以參考這些
   具體數字當測試/範例參數。

3. **對應 ROADMAP 2.5（合約：做空/槓桿/資金費）**：Risk 頁與 LiveTrading
   確認了合約風控欄位：**槓桿上限（預設2倍）、強平價、距強平（保證金率）、
   累計資金費、資金費率倒數、交易所端停損、保證金模式（逐倉/全倉）**。這些
   是「帳戶/倉位層」的欄位，2.5 在引擎裡至少要能算出「強平價、保證金率、
   累計資金費」這三個數字，才能讓之後的 App 層有東西可顯示；「交易所端停損」
   屬於下單層（第4步之後才會真的送到交易所），2.5 這一步不用管，但資料結構
   上可以先預留一個「客戶端停損價」欄位。

4. **參數/欄位命名**：Backtest 頁的「驗證期」一詞用來指「沒有參與調參的
   測試區間」（out-of-sample），如果之後要做 walk-forward 或訓練/驗證切分，
   這是介面上會用的詞彙。

5. **2.8 對照驗證的已知缺口（先前已確認）**：舊對話裡提到的 `docs/reference/`
   Python 標準答案在這個 Mac 專案裡不存在，這份設計稿也沒有提供可以拿來對照
   的原始數據（Backtest/Compare 頁面上的數字是「示意」或「9/23 真實回測」的
   結果快照，不是可重算的輸入資料），所以 2.8 仍然需要另外決定驗證方式
   （例如手算已知解析解的簡單案例），跟這份設計稿無關。

**沒有需要修改目前正在進行中任務（2.1 策略介面 / 2.6 績效指標 / 2.7 內建
策略）驗收條件的地方**——以上發現都是「以後 App 層會用到的細節」，用來
提前避免命名衝突，不是現在就要塞進引擎資料結構的硬性需求。
